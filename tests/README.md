# 验证与验收

当前已有账号、基础档案和初始伙伴的隔离集成测试，运行 `npm test`。更新日期：2026-09-25。

本轮范围与验证见[实现里程碑](../docs/architecture/account-save-milestone.md)。集成测试覆盖下列规格的部分场景，并不表示完整 A/C/D/E 清单通过；初始领宠已局部覆盖，战斗、生产恢复等尚未实现。CI 尚未配置。

## 1. 保留原始公共基线

[总体方案](../docs/overview/design-v0.1.md)第 11 章 C01–C15 保持原编号与含义，覆盖重复请求、并发、事务、越权、断线、生命周期、永久内容、旧存档与恢复。本次只增加专题场景，不替换或削弱原有约束。

## 2. 账号与会话：A01–A10

对应设计：[账号与会话](../docs/architecture/accounts-and-sessions.md)。具体登录方式批准后细化输入和参数；改用外部认证时应更新相关用例而非跳过身份与授权验证。

| 编号 | 场景 | 期望行为 |
| --- | --- | --- |
| A01 | 有效、过期、撤销邀请与并发注册 | 按规则拒绝无效资格；同一邀请不能生成多个账号；响应丢失后能登录恢复 |
| A02 | 正确/错误凭据、未知账号与高频尝试 | 对外响应不随意枚举账号；限流实际生效；普通失败不清档 |
| A03 | 登录、刷新与会话固定攻击场景 | 服务端建立新有效会话；Cookie 与凭据传递符合策略；浏览器标记不能伪造身份 |
| A04 | 当前退出、全部退出、过期和账号停用 | 相应会话不能继续读写；若有长连接，也不能借已有连接绕过；其他会话按策略处理 |
| A05 | 修改密码与同一重置凭据并发/重复使用 | 一次性重置只成功一次；旧密码、旧会话及旧重置凭据按策略失效；资产保持 |
| A06 | 两个账号替换请求 userId、宠物/战斗/活动 ID | 私有数据读写与资产操作均被隔离；不能因知道 ID 获得权限 |
| A07 | 账号恢复与无法证明身份 | 仅通过批准渠道恢复并有受保护记录；不能靠公开信息、默认密码或直接改库接管账号 |
| A08 | 跨站状态修改、错误来源与未通过防护的请求 | 登录和资产变更等按已选策略受保护；不能仅依靠前端按钮或 CORS |
| A09 | 日志、公开响应、构建产物及账号切换缓存 | 不暴露密码/完整令牌/他人私有数据；切换账号后不显示前一账号缓存；生产密钥不打入客户端 |
| A10 | 普通玩家、内容作者、调试账号尝试管理操作 | 未授权请求拒绝；管理动作经过独立认证/授权与审计；Playground 不接触生产资产 |

## 3. 玩家数据与持久化：D01–D10

对应设计：[玩家数据](../docs/architecture/player-data-and-persistence.md)。异常注入仅在隔离测试环境执行。

| 编号 | 场景 | 期望行为 |
| --- | --- | --- |
| D01 | 首次进入、重复初始化、重新登录与换设备 | 档案和初始资产按一次性规则创建；恢复已有进度，不重复发宠 |
| D02 | 两个标签页争用最后一个捕捉道具或同一宠物状态 | 事务/条件更新处理冲突；不负数、不双重成功、不接受整份旧存档覆盖 |
| D03 | 捕捉/领取/进化各写入步骤注入失败 | 消耗、奖励、进度、实例与结果整体提交或整体回滚；没有半份结算 |
| D04 | 数据已提交但响应/推送丢失，再次提交原请求 | 返回原结果，副作用不重复；不因旧 revision 误执行或再次抽取 |
| D05 | 同一操作者复用请求标识但改变参数 | 拒绝冲突，不覆盖已有结果；不同玩家之间不能读取彼此请求结果 |
| D06 | 换 requestId、过期重试缓存后再次领取同一资格 | 业务领取记录仍阻止重复发奖；复刻仅按批准的轮次规则产生新资格 |
| D07 | 战斗断线、会话过期与服务端重启 | 恢复已提交状态和结果；不能重新生成已确认随机结果；玩法超时按规则处理 |
| D08 | 活动停止、收尾、再次开放与正式复刻 | 进度和领取轮次行为明确；永久宠物及其定义、技能、素材仍可用 |
| D09 | 旧存档加载、内容升级、迁移失败和代码回退 | 验证实际兼容性；失败时停止开放，不自动清库；不把数据库回退混同代码回退 |
| D10 | 从备份在隔离环境恢复完整服务 | 核对账号、资产、记录与内容版本；处理旧会话/重置凭据及凭据状态倒退；有实际恢复证据 |

## 4. 后续执行与证据

按需实现规则、内容、集成、兼容和浏览器测试。安全相关测试同时检查失败路径，不以 HTTP 成功或能打开登录页作为通过标准。

每次记录实际候选提交、测试环境、输入、期望、实际结果与可复现证据。尚未执行保持未验证，跳过项目不能作为全部通过。不得弱化公共测试制造通过；独立 Agent 同意不能替代运行结果。

使用合成或适当脱敏样本，不提交生产数据库、密码、会话令牌或备份。文档链接/格式检查与运行测试、安全审计、恢复演练分开报告。

## 5. 首次冒险体验：E01–E12

完整场景只维护在[首次体验设计](../docs/game-design/first-session.md)第 11 节，覆盖主角移动、NPC 选择与领取、各初始候选可玩性、遭遇选择、教学捕捉兜底、双宠入队与协作、挑战失败、断线恢复、常驻可用性、成长及占位素材反馈。

目前这些场景同样未实现、未执行、未验证。它们补充而不替代 C01–C15、A01–A10、D01–D10；具体原型建议冻结后再细化自动化输入，不得用新手保护绕过正式资产校验。

可观察的状态变化、重复领取和恢复路径由运行测试验证；选择是否可理解、配合是否有感知、是否愿意继续探索需要人类试玩记录。20–30 分钟是节奏参考，不是已测性能指标或必须通过的时限。记录实际候选提交、选择组合、卡点和反馈，不把试玩结论伪装成安全测试通过。
