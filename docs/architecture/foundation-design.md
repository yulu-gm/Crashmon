设计状态：Draft。更新日期：2026-09-24。实现状态：基础闭环已部分实现，详见本轮记录。本文是底层设计工作稿，不是正式 API 或已冻结技术方案。

## 1. 已确认方向

常驻系统 + 活动插件，版本内容追求热插拔；小规模多人抓宠回合制；人类设计、Agent 编码与维护。

本次补充明确：账号、登录与用户数据属于常驻系统，不能只留作一个登录页面或活动内部存档。具体注册方式、会话参数、数据库选型及资产规则仍待确认。

以下沿用[总体方案](../overview/design-v0.1.md)中的建议，具体细节仍待确认。常驻系统只服务 Crashmon，不建设通用游戏引擎。

## 2. 首条业务链

先建立最小身份与存档闭环：注册 → 登录 → 初始化玩家档案 → 领取一次初始宠物 → 退出 → 重新登录 → 服务端重启后恢复；使用两个账号验证数据隔离。

再扩展：组队 → 遭遇 → 战斗与捕捉 → 成长 → 保存与重新进入，接入一个可开放、收尾、停用的完整活动。

多人形式和玩法含义以[核心玩法](../game-design/core-rules.md)与[1.0 大纲](../versions/1.0/outline.md)的确认结果为准，不默认独立冒险或同场合作；多个账号可以登录不等于多人合作已经完成。

## 3. 候选公共职责

| 职责 | 负责 | 不负责 |
| --- | --- | --- |
| 账号与会话 | 注册、认证、退出、会话撤销、账号恢复与访问身份 | 用客户端自报 userId 代替认证；让活动独立管理密码 |
| 玩家档案与资产 | 归属、初始化、宠物实例、背包、队伍、消耗与发放 | 为活动绕过公共资产结算 |
| 数据持久化 | 事务、重复请求、并发、快照、迁移与备份恢复 | 接受客户端整份存档覆盖；发布时覆盖生产数据库 |
| 战斗与成长 | 行动、效果、状态、升级、进化 | 在主流程增加具体宠物身份特判 |
| 活动宿主 | 接入、开放、会话归属、进度访问、收尾、清理 | 各活动的专属任务流程；停用时随意清空玩家记录 |
| 内容装配 | 引用校验、内容版本、必要依赖 | 把活动退场等同于删除永久宠物 |
| 客户端表现 | 输入、界面、场景、动画、登录态展示 | 正式伤害、胜负与奖励裁决；认证与数据库秘密 |
| 运营管理 | 必要账号管理、异常查询、受控补偿、操作记录 | 默认给内容作者或 Agent 生产管理员权限 |

职责不要求一一对应类、软件包或服务。

## 4. 依赖与公开能力：待细化

建议内容只依赖公开能力，app 装配公共系统与具体内容。活动不导入其他活动内部实现，框架不主动导入具体活动。

针对首个活动列出最小能力。逐项说明调用方、授权范围、可信输入、输出、失败、重试与持久变化，不提供能访问全部服务的万能上下文。

账号模块建立可信身份；业务服务检查对象归属和当前条件；持久化边界统一提交资产与结果。插件仅获得自己的活动/轮次与必要玩家范围，不获得凭据、任意 SQL 或其他活动的内部数据。

允许具体技能和活动使用清晰业务代码，不强求全部配表。永久宠物需要的规则与素材必须独立于可退场活动。

## 5. 账号、数据与命令

详细正文分别为[账号与会话](accounts-and-sessions.md)和[玩家数据与持久化](player-data-and-persistence.md)，这里不重复维护接口与表结构。

区分账号身份、昵称、宠物种类与实例、活动与轮次、内容与存储版本、数据 revision 和请求标识。登录会话过期、退出登录、停用账号或活动均不默认删除存档。

注册、初始资产、捕捉、领取、兑换、升级和进化需明确原子写入边界。相同请求重试读取已提交结果；一次性奖励还要有独立的业务领取约束，不能换请求编号就重复获得。

断线与重启恢复已提交快照、结果及必要随机状态。数据库结构、唯一性/归属约束、实际访问接口、保留期和恢复目标仍待确认；不因为写了模型表就开始生成未批准的数据库代码。

## 6. 生命周期与版本：待设计

候选流程：加载并校验 → 已加载未开放 → 开放 → 收尾 → 停用。

覆盖加载失败清理、重复启停、拒绝新会话、已有会话结算和强制终止的资产策略。只隐藏页面不等于服务端关闭。

在线启停、内容切换、任意代码不停服替换分别验收。若要旧会话继续运行，需要保留其代码、素材与兼容数据；无法安全共存时明确维护和排空策略。

活动轮次不等于构建版本。重新开放、复刻和归档时明确进度与领取资格；永久宠物和必要记录不能随运行资源一起清理。

模块边界不等于运行时安全沙箱，不默认允许未经审核上传脚本。

## 8. 技术、运行与发布边界：待确认

总体方案建议 TypeScript、2D、模块化单体与轻量存储。根据多人形式和表现需求冻结技术栈与版本，本轮账号与存档已采用 Node.js 原生模块和 SQLite；不因此冻结游戏引擎或安装游戏依赖。

候选组织：一个仓库，客户端和服务端两个构建目标，一套发布流程，可同机部署。共享协议、公开类型与必要纯逻辑，不共享运行时内存，不让客户端导入数据库、认证秘密或服务端专属规则状态。

“常驻系统/活动插件”与“客户端/服务端”是两个维度，活动可同时包含两端部分。生产数据独立于构建产物和静态资源；代码回退不能自动回退数据库。候选版本需要验证旧客户端的兼容与更新行为。
