# 多人同屏据点

日期：2026-09-25。状态：本地共享房间已实现并验证。

## 用户确认与本轮范围

用户要求“按照多人同屏的方式来做”。本轮实现同一服务进程里的共享据点：玩家互相看见角色、昵称和移动，进入/退出同步。该决定确定共享地图，不意味着已经决定合作战斗、PvP、交易或玩家之间的碰撞规则。

每个账号仍独立保存档案与伙伴，教学领取资格不被别人抢占。本轮不修改数据库 schema，也不更改已有伙伴。

## 连接与移动

- 本轮采用同源 HTTP 短轮询，不新增依赖。页面每次成功响应后约 100ms 再同步，最多一个在途请求，实际频率随网络延迟降低。
- 单个请求 3 秒超时；失败后清除远端角色、暂停本地输入并显示重连提示，约 1.2 秒后重试。服务重启丢失房间时重新加入。
- 客户端发送停止、方向或目标点，不上传权威位置。服务器按实际经过时间以 150 像素/秒推进，归一化斜向速度并分步检测碰撞。
- 地图边界、障碍与 NPC 碰撞定义位于 `app/shared/hub-map.js`，由 app 注入房间逻辑；框架不导入具体地图。
- 每条输入最多保持 400ms，失联后不继续无限走向目的地；6 秒无有效新请求移除角色。采用按请求推进和清理，下一个有效房间请求即可看到更新。
- 同一账号只占一个角色。最后加入的页面接管；旧页面收到 409 后停止自动重试，提供“在此页面重新进入”。旧连接不能移走或控制新角色。
- 普通退出立即移除角色，关页尽力发送 leave，异常关闭依靠超时清理。账号停用、会话撤销或过期会停止访问并在下次房间推进时移除。
- 对话/档案界面、页面失焦或隐藏会清空输入。浏览器后台节流可能导致掉线，返回后会重新连接。
- 地图位置和在线列表仅保存在内存。退出、重新加入或服务重启后回到出生区域，永久资产不变。

移动本轮采用服务端快照加客户端平滑显示，没有客户端预测/输入回放。局域网或本机可以验证操作；高延迟公网手感尚未优化。玩家之间暂时可以穿过彼此，出生时尽量选择不同位置；不引入堵门、推挤或抢占 NPC 的玩法。

## 会话与公开数据

房间接口与资产接口一样验证有效会话、账号状态、Origin、自定义请求头及页面账号绑定。每次同步检查连接归属，房间推进复核所有成员会话，复核本身不刷新他人会话的闲置时间。当前页面的同步请求属于认证活动；绝对 7 天会话上限仍生效。

广播仅包含临时地图实体 ID、昵称、坐标和初始伙伴定义 ID，不广播账号 ID、密码、会话、完整背包或存档。只有调用者得到自己的连接 ID。在线人数旁可展开昵称列表；地图中用不同衣服颜色区分自己与别人。

| 接口 | 输入 | 结果 |
| --- | --- | --- |
| POST /api/room/join | 空对象 | 加入共享 hub，返回本人的连接 ID、临时实体 ID 和当前公开快照 |
| POST /api/room/sync | connectionId、sequence、input | 按顺序处理最新移动意图，返回快照；旧序号不覆盖新意图 |
| POST /api/room/leave | connectionId | 只移除该账号、该会话、该连接对应的角色 |

NPC 距离仍用于页面交互提示；初始领取接口延续既有合法候选和一次性资格检查。本轮不宣称已经把所有剧情交互改成服务端地图任务判定。

## 本地体验

执行 `npm start`，使用两个独立浏览器或普通窗口与无痕窗口，分别登录两个账号，访问同一个 `http://127.0.0.1:3000`。每个新账号仍需通过 `npm run invite` 生成自己的邀请码。

普通浏览器标签页共享 Cookie，不能靠两个普通标签页登录两个不同账号；同账号第二标签页会触发接管提示。两个不同端口的独立服务也不是同一个房间。

当前默认服务仍只监听本机回环地址，未开放局域网或公网。其他设备联机需要另行配置可访问的地址、传输保护及部署验收；此轮未自动公开网络端口或部署。

## 验证与限制

集成测试包括双账号接口互见与移动、归属保护、昵称变化、退出、停用、速度与斜向约束、碰撞、输入超时、离线清理、多页面接管、乱序请求、十人出生点和公开字段白名单。

浏览器加独立登录的 HTTP 客户端验证两位玩家：页面在线人数由 1 变 2，可看到另一位玩家移动；第二位退出后回到 1。两个浏览器控制连接中的第二个不可用，因此没有宣称完成两个独立浏览器之间的端到端试玩。另用同账号双页面验证接管和手动重入；实际停启服务验证断线提示与自动恢复。

未完成：多进程/多服务器房间、压测、真实公网延迟、多人战斗、聊天、交易、权威剧情位置验证和跨服存档。玩家永久存档继续使用原有 SQLite 事务边界。
