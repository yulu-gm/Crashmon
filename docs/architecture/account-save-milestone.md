# 注册、登录与存档首个实现里程碑

日期：2026-09-25。状态：首个账号里程碑历史记录；不是正式运营版本。

后续已接入二维据点与初始领宠，数据库升至 schema 2，见[当前原型](../game-design/hub-prototype.md)。本文的 schema 1 与未实现领宠描述对应前一里程碑。

## 范围与依据

本轮用户要求：“战斗可以先不急着收束，先按照 v1 的大致需求跑通用户注册、登录、存档，再登录恢复数据。”

据此实现邀请注册、密码登录、独立玩家档案、手动保存昵称和偏好、退出与再次登录恢复、服务进程重启恢复。暂不接入宠物发放、地图、战斗或正式资产；玩家入门状态保持 `awaiting_starter`。昵称与偏好用于验证真实持久化，不把客户端提交的整份游戏状态作为权威存档。

以下是 Agent 为本地闭环采用的可替换实现选择，不宣称用户已批准所有长期技术方案：Node.js 24+、原生 JavaScript ESM、内置 HTTP/SQLite/crypto、同源 DOM 网页、单进程 SQLite。无第三方依赖，无前端构建步骤。未来游戏引擎、TypeScript 工程与多人模式仍待决定。

## 本轮参数

| 项目 | 当前实现 |
| --- | --- |
| 注册 | 一次性邀请码，7 天有效；命令行生成，数据库仅存摘要 |
| 账号 | 3–24 位 ASCII 字母、数字、下划线；统一小写、唯一 |
| 密码 | 注册 12–128 个 UTF-16 码元，不裁剪；内置 scrypt，N=131072、r=8、p=1、16 字节盐、64 字节派生值；最多同时处理 2 个哈希 |
| 会话 | 32 字节随机凭据；数据库仅存 SHA-256 摘要；7 天绝对过期、24 小时闲置过期 |
| Cookie | HttpOnly、SameSite=Lax、Path=/；HTTPS 配置使用 Secure；本地 HTTP 不设置 Secure |
| 多设备 | 独立会话；退出只撤销当前会话，同一浏览器重新登录撤销原会话 |
| 请求保护 | 写请求严格校验 Origin、JSON 与自定义请求头，不开放 CORS；Host 必须匹配配置地址 |
| 认证限流 | 同一连接 IP 的注册与登录合计每 15 分钟最多 20 次；内存计数，重启重置，不信任转发 IP 头 |
| 数据库 | 外键、唯一约束、WAL、FULL 同步、短事务、user_version=1；未知更高版本拒绝打开 |
| 保存 | 只接收昵称、声音/减少动画偏好、revision、requestId；身份由会话决定 |
| 冲突与重试 | 旧 revision 返回 409；同请求同参数返回原结果，不重复写；同请求不同参数拒绝 |
| 标签页切换账号 | 保存额外比对页面所载入账号与当前会话账号，防止旧页面覆盖新账号 |
| 存档回执 | 本地原型暂不清理；正式开放前定义保留期及过期重试行为 |

scrypt 参数参考 [OWASP 密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。内置数据库接口参考 [Node.js SQLite 文档](https://nodejs.org/api/sqlite.html)。当前本机验证版本为 Node.js 25.8.0；Node.js 24 的内置 SQLite 仍可能产生实验性提示，未在该版本实测。

## 运行

在仓库根目录执行，无需 npm install：

```sh
npm run invite
npm start
```

访问 `http://127.0.0.1:3000`，选择“创建账号”，填入刚生成的邀请码。注册成功后使用账号和密码登录。每次创建新账号都需要新的邀请码。

修改昵称、切换偏好并保存；退出后重新登录，检查内容恢复。可以停止服务，再用相同数据库启动进行恢复验证。`npm run dev` 支持代码变更自动重启。

默认数据库在 `data/crashmon.sqlite`，已被 Git 忽略。可通过 `CRASHMON_DB` 设置独立数据库路径；生成邀请与运行服务必须使用同一路径。`PORT` 可修改端口，访问地址仍使用 `127.0.0.1`。服务只监听本机，拒绝 `NODE_ENV=production`。

运行目录和数据库文件分别按 0700/0600 创建；启动入口设定 0077 umask。数据库含认证与档案数据，不应提交或放入静态目录。服务不提供任意文件访问，只提供三个明确列出的静态资源。

## 接口

| 方法与路径 | 内容 |
| --- | --- |
| POST /api/register | 邀请、账号、密码；事务内消费邀请并建立账号与档案；不自动登录 |
| POST /api/login | 账号、密码；返回公开档案并设置会话 Cookie |
| POST /api/logout | 空对象；撤销当前会话，清理 Cookie，保留档案 |
| GET /api/player | 读取会话所属玩家档案 |
| PATCH /api/player | 保存昵称与偏好；带当前档案 userId 的 X-Crashmon-Player 头、revision 与 requestId |

注册失败响应丢失时，可直接尝试登录；不要假定必须重复创建账号。保存时断网可重试相同请求，或重新读取已保存档案；并发冲突时网页显示提示，由用户重新读取再编辑，不静默覆盖其他页面。

## 验证与限制

执行 `npm test` 运行隔离临时数据库集成测试；`npm run check` 校验代码语法。测试不读取本地体验数据。

当前覆盖：注册与昵称规范化、邀请一次性消费/过期/撤销、凭据失败、闲置会话过期、退出撤销、双账号隔离、旧标签页切换账号、存档重试与并发冲突、事务注入失败回滚、数据库重新打开、真实子进程 SIGKILL 后重启登录恢复。

浏览器手动验证：本地测试账号注册 → 登录 → 修改昵称及两项偏好 → 保存 → 退出 → 再登录恢复。正式验收 C/A/D/E 全量清单仍有未实现项，不能用本轮测试通过代替。

尚未实现：密码更改与账号找回、管理界面、生产级限流与审计、备份恢复演练、完整迁移工具、公开部署、宠物及资产结算、多人玩法。所有临时参数在正式开放前复核；本轮未部署、未访问生产数据。
