## 已确认方向

来源：项目发起人于 2026-09-24 的本次讨论。

| 方向 | 内容 |
| --- | --- |
| 定位 | 小规模多人抓宠回合制；总玩家约 10–20 人、同时在线约 5–10 人 |
| 共创 | 设计者可按版本更换；新宠物通过捕捉或活动获得，可升级进化 |
| 架构目标 | 常驻系统 + 活动插件，版本内容热插拔 |
| 分工 | 人类负责设计，Agent 负责编码与维护 |
| 名称 | Crashmon；仓库 yulu-gm/Crashmon |
| 本轮文档补充 | 账号、登录与用户数据纳入常驻系统，补充专题及 1.0 验收范围 |

本轮依据：项目发起人指出账号与数据缺口，并确认“可以 更新一下项目内的文档”。该授权只覆盖文档更新，不代表批准具体认证方式、数据库、参数或生产操作。

总体方案整体是讨论稿，导入不等于全部批准。

## 2026-09-25：首次冒险体验归档

来源：项目发起人提出先不处理美术风格，初版体验完整后再考虑题材和画风；玩家操控主角，进入地图后在 NPC 处领取初始 Crashmon。随后确认“可以 把这部分初版流程设计放入仓库”。

确认了上述体验方向，并同意将“领伙伴—探索—首次捕捉—双宠协作—区域挑战—成长”整理为后续工作的原型方案。正文见[首次体验](../game-design/first-session.md)，由 1.0 大纲引用；入门内容不绑定限时活动。

具体三选一名单、教学捕捉保护办法、失败恢复、20–30 分钟节奏、技能数值和进化条件仍是原型建议或待细化项，不因归档标记为全部 Approved。多人模式、最终队伍上限、技术栈和正式内容生产清单未由本轮确定。

本次授权限于文档更新；没有新增运行实现、测试执行、部署或正式发奖授权。玩家旅程与账号/存档的工程验收分别维护。

## 2026-09-25：优先实现账号与存档闭环

来源：用户明确要求暂缓战斗收束，先按 v1 大致需求跑通注册、登录、存档与再次登录恢复。本轮授权覆盖本地实现与验证。

Agent 据此采用 Node.js 内置模块、SQLite、邀请注册与服务端会话完成原型；这些是本轮实施选择，不将所有草稿参数标记为人类已批准的长期方案。存档先覆盖昵称与偏好，不决定领宠、战斗或资产规则。范围及验证见[首个实现里程碑](../architecture/account-save-milestone.md)。未部署、未修改生产数据。

## 2026-09-25：二维据点与初始伙伴

用户在“电脑端二维俯视据点 + 三选一 + 确认后不重选”的提案后回复：“可以，做 2d 俯视角，类似宝可梦 go，赛尔号等游戏的视角。”据此完成本地据点移动、NPC 对话、伙伴选择和持久化恢复。

确认范围为上述原型体验；不扩大为战斗、真实地图定位、正式美术或部署授权。原生 Canvas 实现是 Agent 的本轮技术选择。正文见[二维据点原型](../game-design/hub-prototype.md)。

## 2026-09-25：多人同屏据点

用户明确要求“按照多人同屏的方式来做”。据此实现同一服务进程内共享地图、角色移动与在线状态同步，保留各自账号与伙伴归属。多人战斗形式仍待定。

本轮采用服务端权威移动、同源 HTTP 短轮询和每账号一个活跃地图连接，属于原型实施选择；没有扩大为公开部署授权。见[共享据点](../architecture/shared-hub.md)。
