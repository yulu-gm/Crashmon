每只新增伙伴有一张透明四视图标准图，以及一张左右两向、各三种关键姿势的动作图集。普攻与强攻共用蓄势/接触姿势，以位移、跳跃、节奏和效果区分；辅助技能使用独立姿势。战斗待机和地图待机用标准图加轻微呼吸。它们是关键姿势动画，并非骨骼绑定或高帧率逐帧动画。

素材路径为 `app/public/assets/characters/{turtle,bird,scout,shell}/`，最终生成及两次收纳仔返修提示词保存于 [prompts.json](../../art-source/characters/b0/prompts.json)，使用内置 ImageGen。左右姿势真实绘制，巡游仔挎包不靠镜像换边。新角色跟随时可以转向，本轮没有四方向行走动画。

## 稳定产出方法

身份规格 → 标准四视图 → 参考派生的整张动作图 → alpha 与切格检查 → 统一比例与人工锚点 → 时间轴和独立效果 → 放大/实际尺寸/手机/队形验收。

现在的核心问题是生成图不一定严格按格子排布。不要只相信提示词里的“等宽四帧”：实际测量透明度，并允许不等宽源矩形。整段仍使用同一像素比例；按每帧包围盒缩放或自动贴底会造成大小和脚底抖动。图集源像素有实际重叠、缺肢或截断时，返修图像，不能靠取样修复不存在的部分。

```sh
npm run art:check
node scripts/sprite-inspect.js app/public/assets/characters/turtle/poses.png 3 2
```

检查脚本使用 Node 内置模块，不增加运行依赖；只读 PNG，不改图。`art:check` 验证文件、源矩形、透明边界、锚点与技能映射。原始生成图完整保留，运行时使用显式矩形，不另做破坏性的图像切割。少量半透明边缘是抗锯齿；脚本以 alpha≥24 判断主体。

不能保证每次生成都一次成功：本轮收纳仔先纠正了双足站立，随后纠正辅助姿势的朝向。以上流程能发现问题、局部返修并复用参考，仍需人工检查解剖、六瓣伞壳和姿势连贯性。

## 火焰伙伴裁切修复

保留已有火龙外观与 starter_a 身份。旧撞击条图第三帧到 x=1693，却在 x=1629 被切开；喷嚏第二、三帧也串格。现使用实际源矩形与共同参考高度，不把截断的攻击末帧当战斗待机。领宠卡片也增加了上方留白，检查台的小尺寸攻击预览改为播放相同的战斗素材。

旧火焰攻击条图仅有向右姿势，敌方攻击镜像播放该对称旧样本；火焰待机与四只新增角色均使用真实左右视图。这一例外保留在代码中，后续若改变火焰伙伴的非对称装饰，应补真实左向攻击。

## 复用 skill

仓库源文件：[crashmon-sprite-production/SKILL.md](../../tools/skills/crashmon-sprite-production/SKILL.md)。本机通过 `~/.codex/skills/crashmon-sprite-production` 指向同一份源码，可使用 `$crashmon-sprite-production` 调用。技能包含只读 PNG 检查脚本与当前项目资源契约。

素材检查不会修改战斗数值或资产。表现时间轴只播放服务器返回的事件；一次响应内多次行动按顺序演出，同一战斗版本重绘保留进度。关闭战斗停止播放，减少动态效果使用对应方向静止图。
