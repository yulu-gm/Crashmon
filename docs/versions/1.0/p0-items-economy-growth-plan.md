# Crashmon P0：物品、背包、经济、商店与精灵养成实施计划

文档状态：Draft。创建日期：2026-10-06。

本轮授权：编写并归档完整计划；尚未开始本计划对应的功能实施。用户已明确下一阶段制作物品与背包、基础经济与商店、精灵养成，并要求初版 P0 参考早期赛尔号的完整系统。具体数值、进化数量和新增规则仍为提案，归档不等于逐项批准。

本计划是下一阶段范围、依赖和验收的统一入口，不代表整个游戏 P0 已包含所有完整系统，也不替代现有战斗、资产与单只精灵的设计正文。

## 1. 目标与玩家闭环

目标是把已有的战斗、捕捉和存档接成可持续游玩的收集养成循环：

> 领取初始精灵 → 挑战获得金币、经验与材料 → 商店购买补给 → 捕捉野生精灵 → 管理队伍与仓库 → 升级、学习技能、训练与进化 → 挑战更强敌人。

这轮完成后，玩家必须能够理解资源从哪里来、为什么购买物品、怎样培养精灵，以及下一次出发的目标。退出重登后，所有已结算进度可以恢复。

### 1.1 参考早期赛尔号的方式

参考其通用货币、补给采购、捕捉、精灵收纳、等级学习技能和进化形成的循环。官方历史页面提供以下依据，但不作为精确复刻某个历史补丁的完整资料：

- [基础资产说明](https://seer.61.com/main/guide/cycc.html)：基础货币购买装备与战斗道具，通过资源收集及活动获得收入。
- [战斗操作说明](https://seer.61.com/main/guide/jbcz.html)：战斗中使用药品、捕捉胶囊以及管理出战精灵。
- [皮皮图鉴](https://seer.61.com/main/spirit/10.html)：展示进化链、技能学习等级及技能参数。

Crashmon 保留已有四只同时上场、速度行动顺序、共享战术点和四项能力的 B0 基线。性格、潜力、训练等是本计划的适配提案，不据此声称与某年赛尔号完全一致。暂不引入单只出战、技能 PP、物攻/特攻拆分或付费货币。

### 1.2 范围边界

| 本轮纳入 | 本轮不纳入 |
| --- | --- |
| 通用物品定义、物品背包、精灵仓库管理 | 完整剧情对话与任务引擎 |
| 基础货币、奖励结算、固定价格 NPC 商店 | 活动平台、签到、通行证、邮件系统 |
| 战斗道具与场外成长道具 | 交易、拍卖、公会、付费货币 |
| 等级、技能学习与配置、进化、个体培养 | 繁殖、复杂装备、自动挂机 |
| 五只现有精灵的完整成长内容 | 新增第六种精灵、大规模新地图 |
| 必要的旧存档迁移、平衡与独立验收 | PvP、合作战斗、公开部署 |

本轮先利用现有遭遇入口与据点提供完整循环。商店建议由据点 NPC 提供入口，并复用现有菜单入口方便测试；无需等待完整野外地图或剧情系统。未来任务和活动复用奖励结算能力，本轮不预建通用脚本平台。

## 2. 当前基线与缺口

以下为编写时根据仓库文档及现有实现复核的状态，不代表重新完成了运行验收。

| 系统 | 当前状态 | 本轮需要补齐 |

## 3. 物品与背包

### 3.1 物品定义与库存

物品定义与玩家持有数量分离。定义建议至少包含稳定 ID、名称、图标、描述、分类、堆叠上限、可使用场景、目标类型、效果参数、购买价、出售价及是否允许出售。具体字段和存储结构在实施设计中确定。

库存至少支持获取列表、增加、扣除、使用、购买、出售及失败原因。数量必须为有效整数，不允许负数、超上限或通过客户端自定义效果。新增普通药品和球类应主要修改内容配置；确有新机制时再增加效果实现。

首版分类：捕捉用品、战斗用品、成长用品、材料。任务物品与活动货币暂不创建空系统，后续有具体用途时接入。

### 3.2 首批物品清单建议

| 类别 | 建议数量与内容 | 设计要求 |
| --- | --- | --- |
| 通用捕捉球 | 普通、强化两档 | 价格与捕获收益形成选择，普通球持续有用 |
| 属性捕捉球 | 两种属性专用球 | 先确定 T1/T2/T3 正式命名与匹配规则；非对应目标没有额外优势 |
| 恢复药 | 小型、中型两档 | 战斗内单体恢复，满血、倒下等条件有明确处理 |
| 净化药 | 一种 | 明确可移除状态清单，无可移除状态时不消耗 |
| 经验道具 | 两档 | 展示经验与可能的升级结果；规定满级及溢出处理 |
| 训练道具 | 按训练方案确定 | 每件用途明确，训练上限和重置策略一致 |
| 进化材料 | 随五条成长线配置 | 每件有稳定获取来源，避免只能依赖未来活动 |
| 战利品材料 | 少量出售型与培养型材料 | 区分用途，关键培养材料有出售保护提示 |

不为凑数量制作只有名称不同的物品。复活、永久增伤等改变战斗基线的物品不在首批。

### 3.3 背包界面与操作

- 物品背包显示分类、排序、图标、名称、数量、详情、获取途径和使用条件；空背包有明确提示。
- 战斗物品使用“选择物品 → 点击场上合法目标 → 立即执行”，沿用技能交互，不额外增加确认行动。
- 无效目标、库存不足、状态不适用时不消耗、不推进行动；服务器返回具体原因。
- 建议普通战斗道具占用当前行动。捕捉失败仍消耗球与行动，和请求校验失败区分；最终以补充后的战斗正文为准。
- 场外成长道具可先选择精灵或物品，展示使用前后变化；支持合理的数量选择。进化等永久改变使用明确的结果预览与执行按钮。
- 战斗期间可以查看背包，但建议禁止改变正在战斗精灵的等级、形态、技能和训练配置；不允许场外路径绕过战斗快照。
- 物品库存满、精灵仓库满、售罄和断线属于不同状态，不能用同一个失败提示掩盖原因。

### 3.4 精灵队伍与仓库

出战队伍与全部持有精灵分开显示，继续支持 1–4 只队伍配置。仓库支持名称、属性、等级、形态、出战状态等实用筛选或排序；同物种重复个体通过昵称和实例标识区分。

详情页展示基础资料、等级经验、能力来源、已学技能、当前技能、进化条件和培养记录；收藏用于保护与查找。本轮不默认加入永久放生或出售精灵功能。

保留当前 20 只容量作为实施前基线；是否扩大或提供扩容需要单独定案。捕捉前和服务器结算时均检查容量，容量不足的拒绝不能导致扣球或丢宠。仓库容量满后的长期收集体验是验收问题，不能只隐藏捕捉按钮。

## 4. 基础经济与商店

### 4.1 货币、收入与支出

建议只使用一种基础货币，名称待定。钱包显示当前余额，结算显示本次变化及来源。

| 环节 | 首版方案 | 约束 |
| --- | --- | --- |
| 新手资金与补给 | 一次性领取 | 与旧补给领取状态衔接，不重复补发 |
| 普通战斗收入 | 金币与配置化战利品 | 可重复获得，胜负及撤退收益明确 |
| 首次挑战奖励 | 独立的一次性额外奖励 | 首次资格与请求幂等分别判断 |
| 出售收入 | 允许出售的战利品 | 成长材料需提示用途，不能产生买卖套利 |
| 捕捉消耗 | 购买不同捕捉球 | 基础球持续可获得，破产不会锁死成长 |
| 战斗补给 | 药品采购 | 正常挑战收益能够覆盖合理消耗 |
| 培养消耗 | 成长物品、训练与进化材料 | 与金币、经验和进度门槛一并核算 |

保持战斗开始满血的现有基线，不先加入场外付费治疗。没有金币或补给时，玩家仍能通过低风险重复挑战恢复收入；需要用实际低资源账号验证这一点。

### 4.2 商店行为

NPC 商店采用固定商品与固定价格。首版普通补给建议不限量，进阶商品是否随进度解锁待定；不加入随机刷新、每日限购或多种代币。

购买页展示单价、数量、总价、余额、持有量及购买后结果；出售页展示回收单价、数量与用途提示。服务器计算价格并检查物品可交易性，客户端传入的价格不能决定交易结果。

扣款与入库、扣物与加币分别在同一事务完成。请求重试返回同一结果；余额不足、库存超限或商品规则已变化时，返回明确结果供界面刷新。

### 4.3 经济数值表与试玩

开工前建立一张统一数值表，至少包含：遭遇等级、预估战斗时长、金币和经验奖励、掉落概率、捕捉概率、球价、药价、训练成本、升级经验及进化需求。

至少模拟三类玩家：正常推进、重复刷取、连续捕捉失败。检查从低资源状态恢复的路径、每场净收入、一次培养目标所需战斗数，以及购买与出售套利。表格模拟用于发现问题，不能替代真实试玩。

不得直接把当前“普通胜利补 1 球”与新奖励叠加。旧补球、初始补给、教学奖励和首胜奖励如何承接，必须逐项登记并迁移。

## 5. 精灵养成

### 5.1 第一批：基础成长闭环

| 系统 | 必须定义的规则 | 交付行为 |
| --- | --- | --- |
| 等级与经验 | 等级上限、经验曲线、经验分配、满级溢出 | 战斗与道具可连续升级，重登后不重复升级 |
| 能力成长 | 物种基础值、等级成长、取整与最小值 | 预览、详情与实战计算一致 |
| 技能学习 | 各技能学习等级与条件 | 解锁进入已学技能库，有清楚的获得反馈 |
| 技能配置 | 槽位数量、可配置技能、操作场景 | 场外更换后下一场实际生效 |
| 进化 | 等级、材料或其他条件、属性变化 | 主动执行并展示结果，保留同一精灵实例 |

建议保留基础攻击与当前两个主动技能槽位，通过成长扩大可选技能池；不把赛尔号的四技能或 PP 直接覆盖 B0。第一地区覆盖的等级段、版本上限及经验曲线在数值表中定案，不在代码中临时拍板。

经验分配必须明确出战、未出战、倒下、捕获新成员及撤退的处理。当前按参与战斗单位记录经验，调整时需要写出差异和兼容策略。

### 5.2 第二批：个体培养深度

以下仍属于本轮完整 P0 的建议范围；只交付第一批时应标记为阶段完成，不能称完整养成已完成。

- **性格：**采用少量、易理解的四项能力倾向；规则效果与角色描述分开。需要确定初始生成和修正方式。
- **个体潜力：**提供同物种个体差异；限制差距，明确可见信息与后续提升途径，避免初始伙伴因随机结果失去培养价值。
- **训练值：**支持定向培养、单项与总量上限、训练获得来源、重置途径和费用。
- **能力解释：**详情能够区分物种、等级、潜力、性格、训练与临时战斗效果的贡献，展示实际生效结果。

四项能力统一计算，明确各因素的叠加顺序、取整、上限和下限。不能让前端预览、成长后端与战斗内核维护三套公式。

### 5.3 五只精灵的完整内容

建议内容规模：三只初始精灵各三阶段，两只野生精灵各两阶段，共 13 个形态；在当前 5 个基础形态上新增 8 个进化形态。此数量是计划建议，尚未冻结。

| 现有精灵与稳定 ID | 保留的基础定位 | 建议阶段数 | 正文 |
| --- | --- | --- | --- |
| 炉尾狐 `starter_a` | 主动进攻与自身强化 | 3 | [炉尾狐](../../content/pets/starter_a.md) |
| 苔伞龟 `starter_b` | 防护与稳步输出 | 3 | [苔伞龟](../../content/pets/starter_b.md) |
| 星签雀 `starter_c` | 高速标记与配合输出 | 3 | [星签雀](../../content/pets/starter_c.md) |
| 巡游仔 `wild_scout` | 野生高速辅助 | 2 | [巡游仔](../../content/pets/wild_scout.md) |
| 收纳仔 `wild_shell` | 野生护盾与防护 | 2 | [收纳仔](../../content/pets/wild_shell.md) |

每条成长线必须包含属性、定位、能力成长、完整技能学习表、进化条件、各阶段造型与动作、获取方式；野生精灵另含遭遇等级区间、捕获参数与掉落。现有定位是设计出发点，进化应产生可解释的成长与选择。

进化形态必须有实际素材与游戏内表现，不以改名或放大基础图代替。需要检查头像、仓库、地图待机、左右战斗待机、普攻与技能动作，以及采样框、落脚锚点和四对四比例；制作遵循[伙伴素材流程](../../art/creature-pipeline.md)。新增四向行走若超出现有待机能力，另行明确，不因“完整形态”无声扩大范围。

进化保留实例 ID、归属、昵称、收藏、累计经验与培养历史。形态变化导致技能不兼容时须事先给出处理策略，不能静默丢失已学技能。

## 6. 公共能力、存档与战斗接入

### 6.1 一套资产结算

背包、商店、奖励、捕捉和养成共享增加/扣除资产与业务收据能力。服务端校验身份、目标归属、数量、余额、条件和当前版本；货币、物品、精灵变化及操作结果在事务中一起提交。

一次请求成功后即使响应丢失，重试也不能再次扣费或发奖。一次性业务资格与请求 ID 是两种不同约束，均需验证。记录业务来源及必要的前后变化即可，不引入完整事件溯源框架或微服务。

### 6.2 数据与接口设计产物

实施前列出物品定义、玩家库存、钱包、交易记录、精灵成长状态、技能库与配置、内容版本及迁移版本的职责。API 契约覆盖列表、详情、购买、出售、物品使用、技能配置、训练、进化和结果查询；明确输入、返回、权限、错误及幂等行为，路由名称在设计时确定。

复用现有 Node.js 内置模块与 SQLite 原型，不因本计划更换技术栈或安装框架。内容定义与玩家实例分离，价格、奖励与成长曲线可配置，公开接口只支持当前真实需求。

### 6.3 旧存档迁移

| 旧数据 | 必须保证的结果 |
| --- | --- |
| 捕捉球和药水固定计数 | 一次性映射到通用库存，数量不丢失、不重复迁移 |
| 初始领取、补给领取、教学与首胜状态 | 保留已领取资格，新增系统不能重置既有权益记录 |
| 五只精灵实例与重复个体 | 保留 ID、归属、数量、队伍位置和已有外观对应关系 |
| 已累计经验 | 保留原值，明确换算等级规则、上限和溢出策略 |
| 既有技能 | 制定兼容解锁策略，不能无提示剥夺旧精灵已有技能 |
| 新增性格、潜力和训练字段 | 确定稳定默认值或一次性生成策略，不能每次登录重掷 |
| 进行中的旧战斗 | 保留旧规则快照，完成后正确结算到新资产结构 |

迁移需要在隔离旧版本数据库副本验证可重复启动、失败恢复和数据一致性。特别处理旧战斗中的球/药快照与新库存的映射，禁止新旧资产双写产生两套余额。旧存档经验可能远超新版本经验曲线，必须使用高经验样本验证。

本轮不触碰正式存档。未来部署时，代码与数据库版本必须作为兼容组合恢复；不能把旧代码直接指向无法识别的新数据库作为回滚方案。

### 6.4 战斗版本与并发

新战斗从已保存的等级、形态、能力与技能配置创建快照。已有战斗继续使用绑定规则；成长与购买行为不能篡改其技能或能力。

明确战斗期间可执行的操作及库存更新方式。建议允许查看、禁止成长修改；购买与战斗消耗若允许并行，必须通过统一资产事务处理，不覆盖其他操作产生的库存变化。

## 8. 验收清单

### 8.1 玩家完整流程

- [ ] 新账号三选一领取精灵，获得约定补给，首个低风险遭遇能够完成。
- [ ] 战斗获得金币、经验与材料，结算来源可理解。
- [ ] 商店购买普通球、强化或属性球、药品，余额与背包立即同步。
- [ ] 两种野生精灵均可捕获、入库、查看并配置进队。
- [ ] 战斗选择物品后点击合法目标立即执行；没有额外确认行动。
- [ ] 药品、捕捉球的成功、失败、不适用分别按规则消耗与推进回合。
- [ ] 升级使实际能力变化，技能解锁后可配置并在下一战生效。
- [ ] 五只精灵分别完成全部计划内进化阶段与培养流程，素材在实际游戏中正确显示。
- [ ] 低资源账号可以恢复收入并继续捕捉，重复刷取不能无限套利。
- [ ] 桌面和窄屏完成背包、商店、培养与战斗操作，无遮挡、溢出或目标误选。

### 8.2 资产、兼容与边界

- [ ] 重复点击、网络重试和响应丢失不造成重复扣费、发奖或进化。
- [ ] 两个并发请求争用最后一份货币/材料时，只允许符合余额的操作成功。
- [ ] 非法数量、超堆叠、负余额、越权目标和伪造价格被服务端拒绝。
- [ ] 事务中途失败不会只扣钱未发物品、只扣材料未完成培养。
- [ ] 首领首胜、新手补给等一次性奖励不能更换请求 ID 再领。
- [ ] 升级跨多级、满级、经验溢出、训练达到上限、进化条件不足有确定结果。
- [ ] 容量满时拒绝捕捉不扣球，不丢失已有精灵。
- [ ] 退出重登与服务端重启后，货币、物品、精灵、技能和培养结果一致。
- [ ] 旧球药、累计经验、重复精灵、领取状态和旧战斗完成兼容验证。
- [ ] 原有注册登录、共享据点、三选一、队伍与捕捉关键路径未出现回归。

### 8.3 验证方式与完成定义

自动化测试集中在资产事务、权限、重试与并发、迁移、成长公式、战斗联动等高风险规则；前端布局、图标、普通文案和低风险可逆调整通过检查与浏览器试玩验证，不为所有任务机械增加测试。

主 Agent 独立复核实际候选代码、运行结果和浏览器流程，记录数据环境、内容版本与未验证项。内容平衡与乐趣仍需人类试玩，不将单元测试通过等同于完整游戏验收。

本轮完整交付需 P0-01 至 P0-06 的范围均完成；若只完成第一批成长或缺少进化素材，明确登记阶段性交付。现有游戏发布、备份恢复和长期留档要求仍见 [1.0 大纲](outline.md)，本轮本地验收不等于公开运营就绪。
