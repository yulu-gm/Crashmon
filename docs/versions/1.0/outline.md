# Crashmon 1.0 内容大纲

设计状态：Draft。日期：2026-09-24。实现状态：未开始。尚无冻结内容清单、发布日期或上线承诺。

## 1. 本版目标

建议验证：基础抓宠和队伍战斗构成完整循环；一个活动可以独立接入与退场；新设计者和 Agent 能依据仓库继续制作内容。

1.0 覆盖哪些共创和运营演练需要确认。长期留档仍必须满足总体方案的数据、发布与恢复门槛。

## 2. 玩家体验

待确定多人形式、一次游玩目标、设备、二维或三维表现、进入方式。多人形式影响第一条完整流程，不能将多个账号独立登录直接视为完成合作玩法。

## 3. 首条可玩流程：候选

登录 → 获得初始宠物 → 组队 → 基础区域 → 遭遇 → 战斗与捕捉 → 成长 → 保存并重新进入。

再接入一个包含进入、推进、挑战、获宠与退场的活动。若确认合作同场为核心，应在该流程中验证。

## 5. 反推底层需求

实际内容逐项列出需要的公共能力、缺口和验收，回填[底层工作稿](../../architecture/foundation-design.md)。当前没有已经实现的公共能力。

需要公共机制扩展的宠物或活动必须明确提出需求，不夹带框架重构或绕过资产结算。

## 6. 范围限制：待确认

原稿建议先不做实时开放世界、复杂交易、公会、任意脚本上传、复杂繁育、海量装备和完整 PvP 平衡。这些是候选范围控制，不是永久禁止。

需要明确首版热插拔是在线启停、内容切换，还是还包括代码无重启替换。

## 7. 验收与开放

覆盖完整流程试玩、已选多人形式、关键资产操作、重复请求、断线、活动启停收尾和永久宠物保留。长期留档前进行发布与恢复演练。

每个项目登记具体场景和证据，未执行保持未验证；设计文档和目录存在不等于玩法完成。

## 8. 下一轮设计顺序

先定多人形式与首条流程，再确定最小队伍战斗规则，用候选宠物组合和一个活动检验公共能力，同时完善底层设计。不要求一次决定全部远期玩法。
