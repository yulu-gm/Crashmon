# Crashmon 1.0 内容大纲

设计状态：Draft。更新日期：2026-09-25。实现状态：账号、基础档案、二维据点和初始领宠已实现，其余未开始。尚无冻结内容清单、发布日期或上线承诺。

## 1. 本版目标

建议验证：账号和永久数据可靠；基础抓宠和队伍战斗构成完整循环；一个活动可以独立接入与退场；新设计者和 Agent 能依据仓库继续制作内容。

1.0 覆盖哪些共创和运营演练需要确认。长期留档仍必须满足总体方案的数据、发布与恢复门槛；不能先让玩家积累永久资产，再补身份隔离、事务和恢复能力。

## 2. 玩家体验

已确认方向：先完成初版体验，再考虑题材与画风；玩家操控主角进入地图，并在 NPC 处领取初始 Crashmon。完整流程只维护在[首次体验工作稿](../../game-design/first-session.md)，本文件引用范围，不复制具体技能、台词或教学规则。

原型目标是让玩家选择伙伴、亲手捕捉第二只、体验同时上场的配合，并知道下次出发想做什么。先使用功能命名与占位素材；约 20–30 分钟是首次试玩节奏目标，不是已验证时长、倒计时或整版内容长度。

本轮据点已采用二维俯视、电脑优先并兼容窄屏点击；多人形式仍待确认。邀请制账号密码登录仍为建议，见[账号设计](../../architecture/accounts-and-sessions.md)。入门建议不依赖他人在线、不争抢教学机会，但不以独立登录代替多人玩法验收。

账号有效性、会话失效与游戏内断线分别设计，不能让登录模块自行决定战斗暂停或奖励损失。

## 3. 玩家旅程与工程验证

### 3.1 首次玩家旅程

登录后进入据点并自由移动 → 与引导 NPC 交互、选择初始伙伴 → 进入小型野外区域、自主选择目标 → 首次战斗与捕捉 → 第二只加入队伍 → 双宠协作 → 区域挑战 → 成长与后续目标。

首次进化争取在首个完整区域章节内可体验，不强制挤进最初 20–30 分钟。初始候选、捕获对象、教学保护与失败策略见首次体验正文，仍需细化和试玩，不自动生成永久正式配置。

据点、领宠和基础入门流程长期可用；活动插件接在其上提供新体验，关闭活动不能阻断新玩家开始冒险。若确定同场合作是核心，也需在 1.0 完整流程中单独验证。

### 3.2 工程闭环与验收顺序

先验证注册、登录、玩家档案、一次性初始领取、退出重登、双账号隔离和服务端重启恢复，再接入战斗与活动。这是实现和验收顺序，不是让玩家主动退出、刷新和重启的新手任务。

随后验证首次体验全流程与一个可开放、收尾、停用的活动。已有资产安全与发布恢复要求不因先做占位原型而降低；测试内容不擅自发到正式账号。

## 5. 反推底层需求

实际内容逐项列出需要的公共能力、缺口和验收，回填[底层工作稿](../../architecture/foundation-design.md)。当前已实现账号、会话和基础档案持久化；宠物、战斗和活动公共能力尚未实现。

需要公共机制扩展的宠物或活动必须明确提出需求，不夹带框架重构或绕过资产结算。活动作者可以设计获宠条件，正式身份、归属、消耗与发奖由常驻系统保护。

## 6. 范围限制：待确认

本轮先不处理正式题材和画风，但保留移动、交互、行动、伤害、捕捉和队伍变化的可读反馈。主角跟宠、主角独立战斗成长和精细剧情不是首次流程的前置条件。

原稿建议先不做实时开放世界、复杂交易、公会、任意脚本上传、复杂繁育、海量装备和完整 PvP 平衡。这些是候选范围控制，不是永久禁止。

账号侧建议先不做多角色、多区服、短信登录和多种外部账号绑定；不能因此省略账号恢复、权限检查或密码保护。邀请、会话、管理员、备份及保留参数仍需确认。

需要明确首版热插拔是在线启停、内容切换，还是还包括代码无重启替换。

## 7. 验收与开放

验收入口：[公共场景](../../../tests/README.md)。保留 C01–C15、A01–A10 与 D01–D10；首次体验 E01–E12 维护在[体验正文](../../game-design/first-session.md)。自动化验证状态，人类试玩验证理解、选择与节奏，二者不能互相替代。这里只引用范围，不重复维护完整规范。

首次长期留档前，至少提供以下真实证据：

- 注册与登录可用；退出、过期、恢复与账号停用后的访问按规则失效；账号之间不可越权读写。
- 初始宠物只领取一次；重复请求、并发和结算故障不制造或丢失部分资产。
- 退出重进、响应丢失与服务端重启能恢复已确认状态；旧存档有兼容验证。
- 活动启停收尾与永久宠物保留经过验证；测试能力不接触生产数据。
- 实际发布、迁移、备份恢复与账号恢复已演练，权限与责任人明确。
- 完整流程可试玩，选定的多人模式有相应验证，而不是只验证多个账号。

每项登记具体场景和证据，未执行保持未验证；文档和目录存在不等于功能完成。

## 8. 下一轮设计顺序

2026-09-25 最新推进顺序：按用户要求暂缓战斗收束，优先实现注册、登录、存档与再次登录恢复。本轮结果见[首个实现里程碑](../../architecture/account-save-milestone.md)。以下玩法设计顺序留作后续输入。

下一轮先细化初始伙伴的差异、教学捕获候选和第一场双宠战斗，并据此确定最小行动与捕捉规则；再设计区域挑战和首次进化。具体宠物正文进入 docs/content/pets/，通用规则回填核心玩法，不在版本目录复制。

同时保留登录方式、多人形式和数据安全的确认与工程闭环。以具体流程反推底层能力，不先建万能框架，也不要求一次决定全部远期玩法。
