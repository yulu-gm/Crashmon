# 发布与运行维护

当前没有服务器、流水线、备份任务或可执行运维命令。本目录是后续入口，不表示已有生产能力。更新日期：2026-09-24。

参考[总体方案](../overview/design-v0.1.md)第 12–14 章；身份与数据的当前工作稿见[账号与会话](../architecture/accounts-and-sessions.md)、[玩家数据与持久化](../architecture/player-data-and-persistence.md)。

## 首次长期留档前需要形成的运行手册

| 操作 | 必须明确的内容 |
| --- | --- |
| 账号恢复 | 核验渠道、授权操作者、一次性重置、会话撤销、审计；不直接读取或设置玩家长期密码 |
| 账号停用与恢复使用 | 权限、原因、有效时刻、现有连接处理与记录；不默认删除资产 |
| 管理权限 | 首个管理员如何建立、强认证与权限撤销；内容作者和 Agent 不自动获得生产权限 |
| 发布与迁移 | 固定版本与配置、持久化目录、备份、迁移结果、失败停止开放、兼容条件 |
| 备份恢复 | 频率、独立存储、加密与访问、保留期、恢复目标、恢复步骤及实际演练证据 |
| 故障止损与补偿 | 关闭相关入口、保存证据、确认影响、通过受控操作纠正；不直接手改库存 |
| 数据清理 | 账号、活动进度、领取记录、日志及备份的保留与删除规则 |

数据库恢复与代码回退分开授权。恢复旧数据库后需处理会话、重置凭据、账号状态和可能回退的密码记录，不能只验证宠物数量。恢复正式服务前验证相匹配的代码、内容和数据。

运行手册绑定实际环境与命令，并经过演练；尚无实现时不填写虚构命令。生产凭据、玩家数据和备份不得入库。普通 Agent 只使用合成/脱敏数据与必要记录；恢复数据库、删除记录和玩家资产处置均需明确授权。

对应候选验收见 [tests/](../../tests/README.md)。文档检查通过不等于恢复演练或安全审计通过。
