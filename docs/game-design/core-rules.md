# 核心玩法规则工作稿

设计状态：Draft。更新日期：2026-09-25。实现状态：未实现。

## 已确认体验方向

抓宠、队伍同时上场的回合制战斗、每只宠物少量技能、升级和进化。玩家通过捕捉或活动获得新宠物，设计者按版本轮换创作。

玩家操控主角，在地图中的 NPC 处领取初始 Crashmon；现阶段先完善初版体验，再考虑题材和画风。确认来源见[设计决策](../decisions/README.md)。

## 首次体验输入

[首次冒险工作稿](first-session.md)采用“据点领伙伴 → 野外探索与捕捉 → 双宠协作 → 区域挑战 → 成长与下一目标”作为原型流程。三选一、教学捕捉保护与失败恢复方案是待细化建议；双宠教学不等于冻结最终队伍上限，教学成功保护也不等于普通捕捉必定成功。

优先用初始伙伴、教学捕获候选和第一场双宠战斗反推行动、技能、捕捉与成长规则；暂不为未知内容增加复杂机制。

## 本轮规则问题

| 领域 | 待确认 |
| --- | --- |
| 入门流程 | 初始候选与确认后重选政策、教学补给与重试奖励、保护何时结束？ |
| 多人关系 | 各自冒险、共同战斗还是共同地图？如何协作或交互？ |
| 队伍 | 人数、替补、换宠时机、宠物控制权？ |
| 行动 | 顺序、出招等待、技能资源、超时与断线处理？ |
| 技能与状态 | 主动被动数量、目标、持续与叠加、反击追击触发？ |
| 胜负 | 死亡、胜负、撤退、失败代价和重试？ |
| 捕捉 | 目标、时机、道具、成功条件、失败消耗、容量不足？ |
| 成长 | 经验、等级、进化条件、继承与消耗？ |
| 永久持有 | 重复宠物、容量、删除转换、活动结束后的可用性？ |

原方案中的 3 只上场、2–3 个主动技能只是建议，不在这里转为定案。

## 描述与验收

每条规则说明场景、玩家输入、前置条件、成功与失败结果、永久资产影响及可观察的验收例子。不能只写“支持捕捉”就让 Agent 自行决定所有异常行为。

例如同一奖励请求因网络重试再次发送，不应重复发奖。这是行为要求；服务端去重和事务属于底层实现设计。

用[1.0 大纲](../versions/1.0/outline.md)中的实际游玩流程检验规则。具体宠物和活动引用公共规则，缺少机制时在[底层工作稿](../architecture/foundation-design.md)明确提出，不另写一套伤害或资产规则。
