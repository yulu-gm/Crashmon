# 核心玩法规则工作稿

设计状态：Draft（已确认方向与原型规则分别标明）。更新日期：2026-10-06。实现状态：账号、共享据点与初始领取已有原型；B0 本地 PvE、五只伙伴、捕捉和队伍管理已接通，见[验收记录](../verification/battle-2026-10-06.md)。

## 已确认体验方向

抓宠、队伍同时上场的回合制战斗、每只宠物少量技能、升级和进化。玩家通过捕捉或活动获得新宠物，设计者按版本轮换创作。

玩家操控主角，在地图中的 NPC 处领取初始 Crashmon。当前题材为宇宙探索与幽默伙伴，视觉方向见[美术规范](art-direction-v1.md)，不再沿用历史阶段“暂不考虑题材画风”的限制。确认来源见[设计决策](../decisions/README.md)。

## 战斗规则的单一正文

用户已明确队伍最多 4 个单位、由速度决定行动速度。详细的[多单位回合制战斗策划案](battle-system.md)将其展开为原型规则基线 B0；四单位上限取代原稿“三只上场”的建议和“队伍上限待定”的问题。

B0 采用 1–4 只同时参战、连续虚拟时间轴、每单位少量技能、阵营共享战术点、统一状态计时，以及占用当前行动的道具和捕捉。具体公式、数值与边界只维护在战斗正文，不在这里复制。其余补充参数属于待试玩的明确原型方案，不冒充已平衡或逐项批准的正式服规则。

首个战斗原型为单人指挥小队的 PvE，不影响已经确认的多人同屏据点；同场合作与 PvP 仍是后续专题。多人同屏不等于共同结算一场战斗。

## 首次体验输入

[首次冒险工作稿](first-session.md)采用“据点领伙伴 → 野外探索与捕捉 → 双宠协作 → 区域挑战 → 成长与下一目标”。双宠教学不是最终上限，随后可以增加到最多四只。

初始三选一与唯一领取以已确认的[二维据点原型](hub-prototype.md)为准。首次体验旧稿中仍标为待细化的战斗资源、行动成本、教学保护、失败恢复等内容，以战斗 B0 正文为当前原型输入；登录、资产与正式开放验收不被覆盖。正式成长与进化细表继续设计。

三只初始候选、两种野生伙伴和示范首领已接入运行。通过遭遇卡片选择战斗，完整野外尚未实现；首领建议 3–4 只挑战。普通与首领胜利按配置补 1 基础球，教学不发球；本地原型补给与资产边界见[战斗框架](../architecture/battle-framework.md)。

## 据点与初始领取进展

已确认并实现二维俯视据点、NPC 处三选一，最终确认后不能重新领取。详细实现与边界见[二维据点原型](hub-prototype.md)和[共享据点](../architecture/shared-hub.md)。本轮战斗接入保留已有宠物实例和 starter_a/b/c 定义 ID；数据库 v3 兼容迁移增加队伍位置、经验及战斗资产数据。开发和验证使用隔离数据库，不访问真实存档。

## 描述与验收

每条规则说明场景、玩家输入、前置条件、成功与失败结果、永久资产影响及可观察的验收例子。不能只写“支持捕捉”就让 Agent 自行决定所有异常行为。

战斗新增 B01–B30 规格与 F01–F03 验证场景，均位于战斗正文；[公共验收入口](../../tests/README.md)保留 C/A/D/E 场景。尚未执行的规格不能标为测试通过。

用[1.0 大纲](../versions/1.0/outline.md)中的实际游玩流程检验规则。具体宠物和活动引用公共规则，缺少机制时在[底层工作稿](../architecture/foundation-design.md)明确提出，不另写一套伤害或资产规则。
