# 首次冒险与新手体验设计（1.0 工作稿）

设计状态：Draft（体验方向已确认，具体规则与数值待细化）。更新日期：2026-09-25。实现状态：据点、NPC 领宠与恢复已局部实现；其余体验尚未实现。

2026-09-25 后续进展：用户确认二维俯视据点原型，具体三选一与最终确认行为、本轮验证见[二维据点原型](hub-prototype.md)。下文保留完整首次体验草稿，战斗、捕捉与成长继续待细化。

来源：项目发起人提出先完成初版体验，再考虑题材与画风；玩家操控主角，在地图中的 NPC 处领取初始 Crashmon，并同意将后续优化流程收入仓库。确认范围见[设计决策](../decisions/README.md)。

关联：[1.0 内容大纲](../versions/1.0/outline.md)、[核心玩法规则](core-rules.md)、[账号与会话](../architecture/accounts-and-sessions.md)、[玩家数据](../architecture/player-data-and-persistence.md)、[公共验收](../../tests/README.md)。

## 1. 目标与适用范围

首次体验的终点不是“领取了一只宠物”，而是“亲手组成第一支小队，理解伙伴怎样协作，并知道为什么还想抓下一只”。

本轮先使用据点、引导员、野外区域、Crashmon A/B/C 等功能名称和占位素材。用户提出参考宝可梦、赛尔号式主角冒险与领宠体验；这里记录 Crashmon 自己的流程，不确定世界观、正式角色或美术题材。

本流程属于长期可用的入门内容，不随当期活动退场。它可以使用独立内容模块实现，不需要把 NPC、地图或具体宠物身份硬编码到常驻系统核心。

首轮试玩暂以约 20–30 分钟体验“选伙伴—捕捉—双宠协作—区域挑战—看到下一目标”为节奏目标，不设置倒计时，不把它当作已验证时长或完整 1.0 的内容长度。首次进化目标是在首个完整区域章节内可体验，不强制挤进最初 20–30 分钟。

三选一、教学区两种野生伙伴、具体保护办法和内容数量均为原型建议；本次归档不冻结队伍上限、技能、数值、捕捉概率或全部多人规则。

## 2. 玩家旅程与工程验收分开

玩家看到的流程：

```text
完成必要登录 → 进入小型据点并自由移动
    → 与引导 NPC 交互，选择初始伙伴
    → 走出据点，自主选择一个野生目标
    → 第一场战斗与首次捕捉
    → 第二只伙伴加入队伍
    → 双宠战斗，观察一次配合
    → 完成小型区域挑战
    → 感知成长，获得下次出发的目标
```

注册、退出重登、两个账号隔离和服务器重启恢复属于开发与上线验收，不是要求玩家完成的新手任务。账号已经登录时直接恢复游戏，不让每次进入都重新播放领宠流程。

引导按真实进展出现，尽量每次只给一个当前目标。玩家不是靠把教学弹窗全部点完获得资格；服务端已经确认的领取、捕捉和挑战结果才是进度依据。

## 3. 进入据点：先给控制权，再给目标

首次登录后只做必要的身份设置，随后进入地图。暂不加入长篇开场、强制捏脸、连续奖励弹窗或全功能导览。

出生点附近能看见引导 NPC 和候选伙伴。玩家通过一段短路学习移动、靠近和交互；不以强制自动寻路代替这次操作。具体视角、键鼠/触屏输入和交互键随设备方案确认。

当前目标文案可以是：“去前面的引导员处，认识你的第一位伙伴。”这只是功能示例，不是最终剧情台词。

没有宠物时允许在安全据点观察与交互，进入危险区域时明确提示先领取伙伴；不能出现没有解释的阻挡，也不能让玩家带空队伍进入无法完成的战斗。

据点先承担领取伙伴、恢复队伍、通往野外三项功能。一位 NPC 可以兼顾引导与恢复，不为了热闹拆出多个往返跑腿任务。活动入口后续接入，但不在开场同时介绍商店、公会、竞技场和每日任务。

## 4. 领取初始伙伴：一次可理解的选择

原型建议三选一，先验证玩法区别，再确定正式名称、种族与外观：

| 候选代号 | 一句话定位 | 待验证的特点 |
| --- | --- | --- |
| Crashmon A | 更主动地解决敌人 | 一个直接、容易观察的输出特点 |
| Crashmon B | 更稳妥地完成战斗 | 一个简单的保护或减伤能力 |
| Crashmon C | 为下一次攻击创造优势 | 一个容易理解的标记或削弱能力 |

这些是设计占位，不是已经确定的宠物配置。三只都必须能独立完成首场战斗，辅助定位不能让选中它的玩家在得到第二只之前被迫长时间磨血。

选择界面先展示定位、一句技能特点和简单效果演示，允许来回比较后确认。暂不加入随机个体强度、性格、复杂词条或大量属性表，避免把开局变成反复注册刷初始品质。

建议确认领取后，本账号的初始领取资格只使用一次；重复交互显示已有伙伴与下一步目标，不重复发宠。未选择的初始伙伴应保留未来正常获取的设计空间，不制造永久图鉴缺口，也不依赖尚未设计的交易功能；具体途径待定。

领取成功以服务端结果为准，随后更新队伍栏并提示伙伴加入。跟随主角的表现可以后补，不作为初版流程阻塞项。下一目标可以是：“去附近找到一位新的伙伴，再试试它们能怎样配合。”

## 5. 首次探索：小地图，也要让玩家做选择

建议一个小型野外区域，由通向区域挑战的主路和两条短支路组成，支路最终汇合。重点是能够观察和选择，不是地图面积。

原型优先验证可见遭遇与主动交互开战。玩家先看到附近有什么，再决定找哪一只；不在初次探索中每走几步就用随机遭遇打断移动。具体地图同步方式和正式遇敌规则仍待确认。

教学区可先提供两种适合新手捕捉的伙伴，让第二只也包含选择。它们应能与初始伙伴产生可解释的配合，捕获后立即可用，不要求先刷大量等级才能上场。

建议入门流程不依赖其他玩家在线，领取和教学捕捉机会不被他人抢走。是否看见其他玩家、是否共享地图、怎样进入合作战斗另行设计；这不代表把 1.0 的多人目标改成单机。

## 6. 第一场战斗同时承担首次捕捉教学

不强制串联木桩训练、NPC 捕捉示范和重复捕捉三套流程。第一次真实遭遇就教必要信息：

| 时机 | 展示内容 | 玩家要理解什么 |
| --- | --- | --- |
| 首次轮到己方 | 行动者、技能、目标提示 | 谁能行动，怎样下达指令 |
| 首次命中 | 受击、血量和结果反馈 | 自己的选择造成了什么变化 |
| 达到教学捕捉条件 | 清晰的捕捉入口和条件提示 | 何时能尝试获得伙伴 |
| 捕捉结算成功 | 新伙伴、队伍变化和下一目标 | 它现在属于我的队伍 |

暂不一次讲完全部属性克制、状态叠加、长期培养和技能资源规则。出手顺序、捕捉是否占用行动等仍需在核心规则中明确，Agent 不自行补成正式规则。

建议第一场教学捕捉使用明确保护：达到提示条件后保证成功，并告知这是教学规则，不伪装成普通概率。误击倒、退出或资源不足时有可理解的重试入口，不能卡死新手。

保护仅服务于尚未完成的首次捕捉。实现前须明确教学消耗、误击倒奖励、重试补给和保护结束条件；不能用可无限领取的正式道具或重复教学结算实现兜底。获得第一只捕捉伙伴后，后续遭遇按已经确认的普通规则执行，不能通过刷新页面重新取得保护资格。

## 7. 双宠协作与区域挑战

捕捉成功后，在存在合法空位的前提下建议自动加入出战队伍，并提示“下一场战斗它们会一起上场”。保留查看和调整队伍的入口，不强制拖拽教学。双宠指两只同时参战，不等于确定最终队伍上限，也不是传统的一次只派一只、轮流换宠。

第一场双宠战斗只突出一个能看懂的协作例子，例如先施加标记、再利用标记攻击，或保护队友同时保持输出。具体选择取决于下一轮技能与行动规则设计，不在这里规定唯一组合或公式。

成功标准不是机械多点一个攻击按钮，而是玩家能观察到队友改变了另一只的行动结果。战斗应简短清楚，先不叠加大量敌人、插队、追击、反击和复杂被动。初始伙伴与教学捕获目标的合法组合都需要验证，不能只让某一固定搭配顺利通关。

地图中由玩家操控主角，战斗中指挥 Crashmon 小队。建议初版主角暂不加入独立技能、装备与战斗成长系统，避免同时建设两套养成。

区域末尾放一个可见的小型挑战，检验组队与技能选择。失败后应能想到调整顺序或尝试另一位伙伴，而不是只靠大量刷级。新手章节建议返回据点免费恢复再挑战，不损失永久宠物；具体结算、消耗和重试奖励规则仍需确认，不能把本节扩展成全游戏无条件退款。

## 8. 成长与下一次出发

首次体验结束时，目标是拥有一只自己选择的伙伴、一只亲手捕捉的伙伴、一次协作体验、一次可感知成长和一个后续目标。

先用升级与清晰的能力变化提供成长。首次进化建议安排在首个完整区域章节内，完整原型中可以达到，不先依赖多日等待或长期刷取才能验证。等级、材料、选择与继承规则由核心规则及具体宠物设计承载。

进化不仅是数字增长，也应让玩家理解新的能力或定位。即使占位素材没有精美外观，也可以通过技能变化和结果反馈体现差异。

后续目标可来自未捕获伙伴、区域进阶挑战和新活动入口，不必先建设签到、体力或每日任务。已完成新手的玩家回到游戏后继续自己的目标，不强制重走教程。

## 9. 进度、异常与常驻内容边界

以下是需要保存和恢复的业务含义，不要求一项对应一张表或一个状态机框架：

| 检查点或异常 | 体验要求 |
| --- | --- |
| 尚未领取初始伙伴 | 回到据点继续选择，不在登录时自动发一只随机伙伴 |
| 领取结果已提交但响应丢失 | 查询已有结果并显示原伙伴，不能再次消耗资格或重选发奖 |
| 首次捕捉中断 | 恢复已确认的遭遇或按批准的终止策略处理；不能重抽已结算结果 |
| 误击倒目标或教学资源不足 | 有受控重试路径，教学资格与奖励记录不重置成无限资源来源 |
| 已捕捉但客户端没显示入队 | 根据服务端资产和队伍状态恢复，不重新发放第二个实例 |
| 已完成新手或区域挑战 | 不重复强制教程或一次性奖励；复玩奖励须单独定义 |
| 当期活动已停用 | 据点、领宠、基础探索仍可用，已获宠物所需规则与素材仍存在 |

领取、捕捉、奖励、队伍合法性与永久状态由常驻系统裁决，客户端教学提示不是正式资格。账号、事务、并发、断线和恢复细节引用现有专题，不另造一套存档方案。

活动插件接在常驻入门体验之后，提供新的遭遇、挑战与获宠方式。可以在活动尚未开放时完整开始冒险；在正常已确认状态下结束并重新登录也不会丢失伙伴。

## 10. 原型范围与表现要求

建议先用一个小据点、一位引导 NPC、一组初始候选、一个小型野外区域、少量教学捕获目标和一个区域挑战验证流程。候选三只初始、两种野生目标是讨论起点，不是整个 1.0 的宠物总数或美术生产清单。

暂缓正式题材、画风、长剧情、精细动画、复杂角色装扮、主角战斗成长和大规模地图铺设。是否二维/三维、移动方式及目标设备仍需单独决定；暂缓画风不代表默认选定某种技术栈。

占位原型仍需可读的移动、可交互提示、选中状态、行动者、受击、血量变化、捕捉结果、队伍变化与成长反馈。可使用形状、标签、简单位移与缩放；不能把“没做美术”当作不提供可理解反馈的理由。

具体宠物技能与数值写入 [docs/content/pets/](../content/pets/README.md)，具体地图与遭遇待设计后建立内容正文；此处只维护流程与体验要求，不复制宠物配置。

## 11. 候选体验验收：E01–E12

全部未实现、未执行、未验证。原型建议冻结成可执行规则后再填写具体测试输入。自动化可检验客观状态与路径，人类试玩负责理解、节奏与乐趣；不得用“另一个 Agent 同意”代替证据。

| 编号 | 场景 | 检查目标 |
| --- | --- | --- |
| E01 | 首次进入与寻找 NPC | 能直接操控主角、发现目标、完成交互，不依靠强制自动寻路 |
| E02 | 比较初始伙伴、确认、重复交互 | 选择差异可理解，确认后正确入队，一次性领取不重复；关联 D01 |
| E03 | 分别选择每个初始候选 | 每个选择都能独立完成首场战斗，不存在辅助开局软锁 |
| E04 | 野外观察与选择目标 | 可见目标之间存在可理解选择，玩家知道自己为何进入这场战斗 |
| E05 | 首次捕捉、误击倒、退出与资源不足 | 教学保护透明、可重试、不阻断流程，也不产生无限道具或奖励 |
| E06 | 捕获后的队伍与下一场战斗 | 第二只立即可用，合法空位时入队，两只同时参战 |
| E07 | 第一场双宠协作 | 合法初始与捕获组合均可推进；人类能说出一次配合改变了什么 |
| E08 | 区域挑战失败和再次尝试 | 能找到恢复与重试入口，不丢永久伙伴，不强迫大量刷级 |
| E09 | 领取、捕捉、入队过程中断线或刷新 | 恢复服务端已提交结果，不重发、不重抽；关联 A04、D04、D07 |
| E10 | 无其他玩家在线、活动停用 | 仍可完成入门，教学机会不被争抢，永久内容可用；关联 D08 |
| E11 | 首次成长与区域章节进化 | 成长反馈可理解；进化可在完整原型中验证；玩家知道后续目标 |
| E12 | 全占位素材完整游玩 | 交互和结算能看懂；记录实际时长、停顿、求助及误解，不以美术完成度替代体验判断 |

试玩至少记录版本/提交、初始选择、捕获选择、完成时间、卡点、重试与玩家反馈。重点询问：为什么选这只？第二只是否改变操作？接下来想抓谁或尝试什么？约 20–30 分钟只作节奏参考，不靠强行缩短对话或替玩家操作来制造达标。

公共安全与数据验收 C01–C15、A01–A10、D01–D10 仍独立保留；体验通过不能替代它们，也不代表已经达到正式运营条件。

## 12. 下一轮设计输入

后续确认：二维共享据点现已实现玩家同屏与位置同步，见[共享据点](../architecture/shared-hub.md)。多人战斗及捕捉交互仍未确定。

优先细化初始伙伴的技能特点、教学捕获候选与第一场双宠战斗，借此确定最小行动规则和捕捉操作。随后设计区域挑战、初次进化与后续目标。

实施前明确：输入与视角；初始候选与领取后重选政策；普通捕捉及教学保护的完整范围；目标误击倒和教学补给的奖励限制；战斗失败消耗与重试；队伍上限、行动顺序和资源；进化条件；入门与选定多人模式的衔接。

本次只归档体验设计并连接已有文档，不生成运行代码、正式 API 或假定已存在的测试命令。
