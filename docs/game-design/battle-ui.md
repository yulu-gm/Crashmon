# 战斗与伙伴界面 B0

实现候选：2026-10-06。自动检查与真实浏览器验收由主 Agent 记录；本文不代替运行证据。

沿用赤沙海岸的深色金属、暖沙金与薄荷绿，固定二维 Canvas 舞台搭配 DOM 控件。战斗中显示固定阵营槽号（例如“巡游仔·我3”），统一用于行动条、场上单位、目标、记录与舞台，同种实例也能区分。五只伙伴共用常驻图鉴：炉尾狐复用已有角色素材，其余使用程序绘制，保留轮廓、眼睛、配色、护盾及行动表现。设计与数值正文见[宠物内容](../content/pets/README.md)。

营地右上「探索 · 伙伴」提供野生遭遇与五只伙伴图鉴，独立的「Crashmon背包」入口直接展示全部持有伙伴。背包包含名称、形象、定位、可区分的伙伴编号、出战／后备状态与经验；同种不同实例分别列出。队伍调整复用背包列表，点击「调整出战队伍」进入编辑并明确保存，战中可查看背包但不能改队。初始领取仍由引导员触发，只能三选一一次。图鉴说明性格、栖息地、获得方式、外观、动作、完整基础值、普攻与两个技能。队伍支持 1–4 个持有实例，战中锁定；后备伙伴不会被丢弃。

战斗弹层展示服务端当前行动者、双方战术点、最多八次预计行动、生命、护盾、状态持续、首领意图。普攻与两个主动技能以独立技能卡展示名称、费用、目标、效果和资源不足原因。先选择普攻、技能、道具或捕捉，再点击合法场上单位立即提交，不再增加“确认行动”。自身技能与防御也需点击当前行动者；全体技能点击任一存活敌人即对全部敌人释放。未选动作时点击单位只选中，不执行行动。捕捉在选择工具后提前列出所有目标概率与资格；非法目标只解释原因。场上单位的透明语义按钮与 Canvas 共用槽位布局，支持 Tab / Enter；非法目标通过悬停、聚焦和点击解释原因。捕捉使用服务端概率并明确教学半血保护。战后展示真实结算经验与捕捉球，持有伙伴由服务端档案恢复。

客户端只提交指令，不决定伤害、掉落或捕捉结果。请求失败保留原 requestId，提供安全重试和同步最新进度；同标签页刷新也保留待确认请求。登录自动恢复进行中的战斗。关闭面板返回营地不等于撤退；撤退在单独展开的说明内明确确认。战斗进行中 24 小时不活跃的放弃规则在出发前说明。

所有核心操作都是键盘可聚焦按钮，弹层阻断地图移动，Esc 关闭面板。生命数字、细血条、护盾和状态短标直接悬浮在场上单位头顶，不设深色底板、圆角容器或角色卡。无状态时不显示“状态正常”占位行；状态短标保留悬停的完整名称与回合，辅助技术读取完整中文说明。当前行动者用金色脚底圈与小箭头，选中目标用青色虚线脚底圈，头顶 HUD 不加选中框。首领意图放在舞台下的简短预告。双方集中为独立阵营：桌面我方左下、敌方右上，阵营内最多 2×2，中央留空；窄屏敌方在上、我方在下，各方仍最多 2×2，避免混成同一网格。地面淡色环与“我方 / 敌方”标识强化区分，单个敌人在敌方区域居中；内容可滚动，切页或进入新战斗回到顶部，同场行动保持滚动位置。舞台单位按独立槽位布局，双方阵型与透明点击层共用坐标，舞台高度按本体和实际状态需要安排，头顶 HUD 贴近各自本体。减少动态偏好及系统 reduced-motion 均禁用位移动画，正式结算仍照常显示。

接口层在 `app/public/battle-client.js`，表现层在 `battle-renderer.js`，主题在 `battle.css`；营地绘制复用伙伴表现函数。程序绘制资源属于原型候选，尚不代表完整美术制作与平衡定案。
