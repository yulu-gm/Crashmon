# 二维据点与初始伙伴原型

日期：2026-09-25。状态：二维据点里程碑记录；战斗、野外和正式美术未实现。

后续已实现[多人共享据点](../architecture/shared-hub.md)，移动位置改由服务端内存状态裁决；下文“本地移动”的描述对应此前里程碑。

## 本轮确认与范围

用户同意上一轮“据点移动 → NPC 对话 → 初始伙伴三选一 → 保存 → 重登恢复”的推进方案，并明确采用二维俯视角，参考宝可梦 GO、赛尔号等游戏的视角感受。此处采用平面俯视地图与略带正面的角色、建筑表现，不接入真实地理地图或定位功能。

本轮按已接受方案实现 A/B/C 三选一、最终确认后不能重选。使用功能命名与几何占位外观；宠物定位来自首次体验工作稿，技能、属性、等级与战斗数值继续待定。未选择的伙伴未来获取途径仍待设计。

## 操作与体验

- 登录或恢复会话后直接进入小型据点，档案放入右上角菜单。
- WASD、方向键移动；点击地面向目标直线移动，遇障碍停止或沿边滑动，不包含自动寻路。
- 主角从广场南侧出生，向北找到引导员；交互范围内出现提示，按 E 或点击交谈。
- 对话里可以比较三位伙伴，进入最终确认后仍可返回；最终点击“确认领取”才会创建永久宠物实例。
- 成功后自动加入队伍第一位，左下角显示伙伴与已保存状态；再次交谈显示已有伙伴。
- 对话、档案菜单和页面失焦时停止移动，Esc 可关闭对话；领取请求执行中暂时禁止关闭，避免误以为取消成功。
- 据点建筑、池塘、树干与未开放出口具有简单碰撞。野外出口标注“筹备中”，当前不能进入。
- 桌面显示据点全貌；窄屏采用局部视野并水平跟随主角，支持点击移动。

主角位置属于本轮客户端表现状态，刷新或重登回到据点出生点。持久保存的是账号、昵称、偏好、宠物实例、队伍位置与领取资格。没有把移动位置伪装成已经实现的多人同步或服务端地图判定。

## 技术与数据边界

沿用原生网页，新增 Canvas 2D 地图和 DOM 对话框，不安装第三方依赖；这是当前原型选择，不冻结后续游戏引擎。

`content/pets/starters.js` 存放常驻初始伙伴定义，由 `app/server.js` 装配。常驻存储接收允许领取的定义 ID，不主动导入具体内容。宠物定义不归属于可退场活动。

数据库从 schema 1 事务式升级到 schema 2，新增 `pet_instances` 和 `starter_claims`，保留已有账号、会话、档案与保存回执。不重建旧玩家表；旧表的 onboarding 列保留作兼容字段，公开入门状态以唯一领取记录推导。

- 每个账号只有一条初始领取记录，数据库主键保护一次性资格。
- 宠物实例、队伍位置、领取记录、玩家 revision 与响应回执在同一个事务内提交。
- 相同请求、相同选择返回原结果；换请求编号也不能重复发宠。已领取后请求不同伙伴返回冲突。
- 初始伙伴自动入队第一位不等于冻结最终队伍上限。
- 客户端只能提交候选定义 ID 与请求 ID，不能指定玩家归属、宠物实例 ID 或技能数值。
- 会话、Origin 和页面账号绑定校验沿用账号里程碑。

新增接口：`GET /api/starters` 返回登录玩家可见候选；`POST /api/starter` 执行唯一领取。`GET /api/player` 新增 pets 数组与由领取状态推导的 onboarding。

NPC 距离门槛目前在客户端交互层；服务端保护身份、合法候选和唯一领取资格，不宣称已具备权威地图位置校验。后续有区域解锁或地图经济条件时，应接入服务端状态验证。

## 验证

本轮 `npm test` 共 11 项通过。新增覆盖领取重试、不同选择并发、重新登录、实例不重复、非法候选、跨账号请求、事务失败回滚、v1 存档迁移和领宠后旧版本保存冲突；进程强制终止测试扩展为验证宠物实例恢复。

独立本地测试账号试玩：远处按 E 无交互 → 点击移动靠近 → E 对话 → 比较 A/B/C → 返回比较 → 确认 C → 自动入队 → 重复对话 → 刷新 → 退出重登，均符合预期。1280×720 与 390×844 画面经过截图检查；窄屏点击移动和交互可用。不是手机实机或全部浏览器兼容认证。

本地现有数据库升级前保存了一份 SQLite 一致备份，存于 Git 忽略的 backups 目录；未修改已有账号的选择、未替用户领宠、未发布部署。
