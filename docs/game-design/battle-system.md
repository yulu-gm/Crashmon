# Crashmon 多单位回合制战斗策划案

版本：v0.1 / 原型规则基线 B0。更新日期：2026-10-06。

设计状态：Draft（明确的原型规则，不是已平衡的正式服参数）。实现状态：本次仅文档归档；已有角色攻击演出样本不等于战斗系统已实现。

确认依据：用户明确“一次可以准备一个队伍（最多4个单位），每个单位由速度来决定行动速度”，并要求“写成明确的多单位回合制战斗策划案，放入项目并推送 GitHub”。四单位上限与速度驱动是已确认要求。其余沿用本轮提案并补齐为可验证的 B0 规则；数值、自动放弃时限和战后恢复等补充方案仍需人类试玩或权益确认，不冒充已逐项批准。

本文是战斗规则的单一正文。实现原型时按 B0 执行，不让 Agent 自行在多个候选机制中挑选；需要调整时更新本文和对应验收。本文不批准部署、修改现有账号资产或把测试数值发到正式玩家。

## 1. 体验目标与首版边界

战斗要让玩家判断：谁先行动，怎样利用队友，何时消耗资源，何时保留目标以便捕捉。参考宠物收集与培养、小队协作与行动序列的体验，不声称复刻宝可梦或星穹铁道的原始规则与公式。

B0 先验证一名玩家指挥自己的小队进行 PvE；已有多人共享据点继续保留。这不是将整个项目改为单机，也不是已经确定合作战斗的控制和收益分配。

| 项目 | B0 规则 |
| --- | --- |
| 队伍 | 1–4 只宠物，同时上场；不要求凑满 |
| 行动 | 连续虚拟时间轴，速度影响行动先后与频率 |
| 输入 | 轮到哪只，就为哪只提交一条指令；思考与动画不推进逻辑时间 |
| 指令 | 普攻、主动技能、防御、道具、捕捉；撤退是终止整场的明确操作 |
| 技能 | 每宠 1 普攻、最多 2 主动、最多 1 被动；开局可只开放 1 个主动 |
| 技能资源 | 各阵营独立的共享战术点，开局 3、上限 5 |
| 战场 | 敌方 1–4 个单位；无前后排、距离、相邻加成 |
| 暂不支持 | 战中换宠、替补、召唤、复活、额外行动、打断、行动外终结技、复杂反击连锁 |

四只上限取代旧稿“三只上场”的建议及“上限待定”的表述。新手仍按单宠开局、双宠教学、后续逐渐扩充队伍推进。

## 2. 战前准备与参战资格

进入战斗前显示敌人概况、是否可捕捉、挑战奖励和特殊规则；玩家可以调整队伍与已解锁技能。确认后锁定本场成员、属性、技能、控制者和内容版本。

同一宠物实例不能重复上场，必须属于当前玩家；不同实例是否同种不作额外限制。主角不作为第五个战斗单位。每账号最多一场未结束战斗，进行中不能把参战实例用于另一场战斗、进化、放生或交易，也不能通过外部改队影响本场快照。

B0 为独立遭遇：进入时全员满生命、无上场战斗的护盾与状态，战术点重置为 3。战斗结束后清除战斗临时状态，下场重新满血；不建立跨战斗伤势与补给压力。NPC 恢复可作为归站表现，不要求玩家为恢复重复跑腿。这是便于先验证战术的原型选择，不代表永久排除长途资源管理。

捕获的新伙伴归入永久持有，但不进入本场行动队列；战后有合法空位才自动编入队伍，否则进入持有列表。不得丢弃宠物或自动替换已有队员。

## 3. 行动时间轴

### 3.1 术语与公式

- **虚拟时间 T**：只用于决定行动次序，不是现实秒数。
- **行动进度 P**：每单位独立积累，满值为 10000。
- **行动机会 / 单位回合**：该单位从被选中、处理回合开始，到指令与回合结束处理完成。
- **主行动**：一个行动机会内，成功提交的一条指令。

不存在“所有单位各行动一次”的全局回合。初始 T=0、所有 P=0；当速度恒定时，完整行动间隔为 `10000 / SPD`。

| 速度 SPD | 完整间隔 |
| --- | --- |
| 80 | 125 |
| 100 | 100 |
| 125 | 80 |
| 150 | 约 66.6667 |

下一个行动等待值为各存活单位 `(10000-P)/SPD` 的最小值。一次性将 T 推进该值，同时给每单位增加 `SPD × 推进值` 的进度。满进度者按同速规则选出一位执行；主行动和回合结束处理完成后，若仍存活，其 P 重置为 0。

玩家思考、掉线、选择目标和观看动画都不推进 T。敌方由服务端在自己的行动机会选择指令，也不靠客户端动画驱动。

### 3.2 同时就绪、速度变化与精度

开战时生成并保存一个全场唯一的 `tieOrder` 顺序，用来打破同时就绪的平局；两方都参与，不永久偏向玩家方。其结果可从实际行动条看见，恢复或刷新不重抽，不每次轮转重新洗牌。

加速、减速保留已积累的 P。等价的剩余等待修正为：`R新 = R旧 × SPD旧 / SPD新`。例如速度 100、剩余等待 40，变为速度 125 后剩余等待 32。速度回落也按同一原则计算。

已满进度的单位即使被减速也仍然就绪；当前已选中的行动机会不会被普通加减速夺走。自身在行动内变速，完成本回合的状态扣减后再以最终速度开始下一次积累。B0 没有立即行动或直接修改 P 的技能。

内部计算不能使用界面已四舍五入的等待数。实现需采用统一的可序列化数值策略；同一服务端的计算、存档恢复与预览必须一致。数学上同一时刻就绪的测试用例要识别为平局，而不是让浮点误差替代 tieOrder。

### 3.3 最小可复核例子

A=150、B=100、C=75，tieOrder 为 A、B、C，无状态：

| 虚拟时间 | 行动 |
| --- | --- |
| 66.6667… | A |
| 100 | B |
| 133.3333… | A，然后 C（同一时刻） |
| 200 | A，然后 B（同一时刻） |

速度改变的是频率，不是让所有单位每轮仍固定只动一次；时间显示可以简化，内部平局不能丢失。

## 4. 一次指令如何完成

一个行动机会的时序固定为：

```text
选出就绪单位
  → 移除“到本次行动开始”为止的状态，例如防御
  → 记录可在本回合结束时扣减的既有状态
  → 结算回合开始效果，例如灼烧
  → 检查倒下与终局
  → 若仍可行动，进入等待指令（敌人则选择指令）
  → 验证指令、目标和成本
  → 扣除成本，执行主效果
  → 执行允许的被动效果
  → 主行动整体结束，处理标记消耗和普攻回点
  → 对仍存活的行动者扣减合格状态，移除到期状态
  → 重置其行动进度，判断终局，保存结果
```

回合开始后若单位已被灼烧击倒，不再等待该单位输入、不扣道具、不回战术点。回合开始与“等待输入”位置必须保存，重连不能再跳一次灼烧。

非法指令不消耗行动、战术点、道具或随机数。收到合法请求后，成本、效果、状态、随机状态、资产变动和回执必须一致提交；技术失败不能留下半次行动。

单体技能只选择合法存活目标；目标失效时拒绝请求，不静默换成另一个目标。全体技能在主行动开始时确定目标集合。同一范围伤害效果同时写入各目标生命后再统一处理倒下，避免遍历先后改变群攻结果；后续效果与后续段数不再作用于已倒下目标，不自动转火。

## 5. 指令、技能槽与共享资源

| 指令 | 目标与效果 | 战术点 | 行动机会 |
| --- | --- | --- | --- |
| 普通攻击 | 单体直接伤害；各宠物有自己的表现和攻击属性 | 主行动完成后 +1，达到 5 后不再增加 | 消耗 |
| 常规主动 | 按技能定义选择自身、友方或敌方 | 1 点 | 消耗 |
| 强力主动 | 较强输出或支持能力，无行动外插入 | 2 点 | 消耗 |
| 防御 | 自身直接伤害减半，至自己下次行动开始 | 不变 | 消耗 |
| 恢复道具 | 默认仅治疗一名存活队友；不复活 | 不变，扣 1 个道具 | 消耗 |
| 捕捉 | 一名仍存活、可捕捉的敌人 | 不变，按第 9 节扣道具 | 消耗 |
| 撤退 | 当前玩家行动机会放弃整场战斗 | 不变，无额外费用 | 战斗直接终止 |

普攻回点按主行动一次计算；多段、群攻、打到护盾或额外表现均不额外回点。被动和持续伤害不回点。有效普攻即使最终只击中护盾，仍回 1 点。防御不产点，不能通过无风险连续防御蓄满资源。

资源不足时技能不可提交。敌方也只有独立的一池 3/5 战术点，遵守相同成本。B0 不同时叠加独立蓝量、PP、冷却、终结技能量和命中率系统。

技能定义必须写清 ID、解锁条件、指令类型、目标范围、费用、按序效果、属性、状态时长和表现引用。最多 2 个主动槽位，不开放战中换装技能；未解锁槽不显示假按钮。

## 6. 属性、伤害、治疗与护盾

### 6.1 四个核心数值

生命上限 HP、攻击 ATK、防御 DEF、速度 SPD。生命为 0 即倒下。本版无物理/特殊拆分、随机暴击、闪避、伤害浮动、个体值和装备词条；属性不能随客户端请求任意变更。

B0 普通宠物基础速度建议落在 80–120；测试例子可以超出。ATK/DEF 的百分比修正分别先相加，再限制在 -50% 至 +100%；SPD 修正限制在 -50% 至 +50%。有效值最后向下取整，ATK、SPD 最低 1，DEF 最低 0。不支持速度 0、战斗内改变生命上限或无限堆叠加速。

### 6.2 伤害与取整顺序

`原始直接伤害 = ATK × 技能倍率 × 100/(100+目标DEF) × 属性倍率 × 标记倍率 × 防御指令倍率`

正倍率的有效直接伤害在全部乘算后向下取整且最低为 1。每段独立取整；技能配置必须明确段数与每段倍率。先扣护盾，再扣生命，最终实际生命损失不超过目标剩余生命。固定伤害、反伤和吸血不属于 B0 公共能力。

算例：ATK=40、倍率=1.5、目标 DEF=50，普通伤害为 40。克制 1.25 得 50；再有标记 1.25 得 62（62.5 向下取整）；再遇防御 0.5 得 31。有 20 护盾时，本段扣 20 护盾和 11 生命。

治疗与新护盾量按 `floor(施法者ATK × 配置倍率 + 配置固定值)` 计算，不受属性克制、标记和目标 DEF 影响。治疗不超过缺失生命，不能治疗倒下单位；满血目标禁止纯治疗指令，避免无意义消耗。

### 6.3 小型属性关系

每宠一个主要属性，每个伤害效果一个攻击属性；不提供同属性额外奖励、双属性或免疫。关系只有克制 1.25、普通 1、抵抗 0.8。

正式名称与首批种族归属待内容设计。无题材测试采用 T1→T2→T3→T1 的克制环；反向为抵抗，同类与中性均为普通。T1/T2/T3 是测试代号，不写进正式图鉴；缺少属性配置的测试单位明确使用中性，不猜测“火一定克制石”。

### 6.4 单护盾池

每单位只有一个护盾池。新护盾高于或等于旧剩余量时替换数值并更新为新时长；较弱护盾不叠加，也不刷新较强护盾的寿命。护盾默认持续目标之后的 2 个单位回合，耗尽即移除。界面显示护盾量与剩余时长；护盾不是第二条可被当作捕捉生命的血条。

## 7. 状态与持续时间

所有“回合”必须说明参照谁。B0 常规状态统一按受影响单位的回合计时，禁止宠物脚本私自按全局轮次或现实秒数计时。

| 状态 | B0 基线 | 触发与结束 |
| --- | --- | --- |
| 灼烧 | 每次 `max(1,floor(目标最大HP×0.05))`，持续目标 2 回合 | 目标回合开始扣除；不吃 DEF、属性、标记、防御；先吸收护盾 |
| 标记 | 下一次主行动的直接攻击对该目标 ×1.25，最长目标 2 回合 | 整次攻击后消耗；多段都生效，持续伤害不消耗 |
| 攻击/防御上升或下降 | 单项 ±20%，持续目标 2 回合 | 同一类别不叠层；正负类别按第 6 节合计 |
| 加速/减速 | ±20%，持续目标 2 回合 | 立即保留进度重算；到期同样重算 |
| 防御指令 | 直接伤害 ×0.5 | 至自身下一次回合开始，先到期再结算灼烧 |
| 护盾 | 按技能数值，默认目标 2 回合 | 规则见第 6.4 节 |

行动机会开始时记录当时已有状态。只有这批状态中本回合没有新施加/刷新的实例，才在回合结束扣 1；新状态和刚刷新状态不在同回合立即损失时长。状态要能区分本次刷新与旧实例，不能仅凭相同 ID 错误扣减。

例：A 在 B 行动前给 B 加 2 回合增益，B 接下来两次回合结束分别变成 1、0。A 在自己本回合中给自己加 2 回合增益，不扣本回合，之后两次回合结束才扣。

除护盾外，同名状态重复施加保留较强幅度，剩余时长取旧值与新值较大者，不把时长相加；灼烧不因多个来源变成多层独立跳伤。攻升与攻降、加速与减速各是不同状态，可共同存在。非护盾状态无法通过低数值重复无限叠强度。

标记在一条主行动首次对该目标造成有效直接伤害时锁定为本次攻击的加成，覆盖该次主行动的全部伤害段；即使伤害都被盾吸收也算使用。该主行动中新加上的标记不回头强化本行动，只服务后续攻击。结束时仅消耗被使用的旧标记，不能误删本行动后来施加的新标记。

高速单位更快迎来自身回合，因此灼烧与按自身回合计时的增益也更快结算/到期，这是明确规则，不是显示错误。倒下或被捕捉时移出队列并清除临时状态。

## 8. 被动与技能组合边界

B0 的被动只允许条件系数修正、开战一次效果、或自身主行动完成后一次治疗/护盾/普通属性状态；不产战术点、不消费背包、不产生新的行动或追加攻击。开战效果在 P 初始化后、首次推进前按 tieOrder 处理。

同一个被动在同一次主行动最多执行一次，多段或群体不按命中数量重复执行。被动产生的事件不再触发其他被动；本版不提供死亡反击、反弹、连锁追击与复活。单位倒下后不再执行被动。

内容作者可以写清晰的条件分支，但只能读取受限战斗视图、请求白名单效果；不得直接改时间轴、随机源、数据库、账号资产或其他插件状态。伤害/治疗/状态与捕捉统一结算。每个技能先限制为最多 4 个按序的主效果，超出需求作为公共能力扩展讨论。

保护型与辅助型初始伙伴也必须有正常普攻和单宠可用技能。配合技能不能变成“没有指定队友就无法推进”的硬锁。幽默只改变演出和文案，不允许随机不听指令或吞掉玩家资源。

## 9. 捕捉、道具与教学保护

### 9.1 普通捕捉

捕捉使用当前己方单位的行动机会，但不使用它的攻击力，也不给主角独立排一次行动。必须同时满足：目标存活、属于本场敌方、标记为可捕捉、道具够用、持有容量合法。盾量不作为捕捉血量；不可捕捉的首领要在战前和选中时提示。

为避免实现时临时发明概率，B0 提供一个临时计算基线：

`h = 当前生命 / 最大生命`

`p = clamp(物种系数 × 道具系数 × (1 - 0.75h), 0.05, 0.95)`

普通测试种物种系数为 0.8、基础球系数为 1；满血 p=20%，四分之一血 p=65%。系数与所有正式物种配置需后续平衡。本版不叠加异常状态或玩家等级修正。

概率由服务端返回用于显示；结算以服务端当时有效状态重算，不信任客户端自报概率。服务端抽取 `[0,1)` 的随机值 r，`r < p` 才成功；无效请求不抽取。重试必须返回原结果而不是重抽。界面显示的百分数可以保留一位小数，不能把近似显示值当成计算输入。

有效尝试不论成功失败，都消耗 1 个对应捕捉道具和本次行动。失败时目标保留生命和状态。成功时目标立即退出本场，唯一创建宠物实例并保存捕获记录；其余敌人仍在则继续，最后一个敌人被捕获则按胜利结束。

捕获立即成为永久资产；随后战败、撤退或超时放弃仍保留。已经消耗的道具也不返还。目标本次遭遇实例只能创建一个宠物，换 requestId 不能重复捕获。新宠本场不参战，战后按第 2 节入队；不继承敌方首领加成、临时状态或未批准的特殊技能。

### 9.2 首次教学捕捉

仅在服务端授权的首次捕捉遭遇中生效，选定教学目标生命不高于 50% 时保证成功，并明确提示“教学捕捉：条件满足后必定成功”。条件未满足时不能提交教学捕捉，不消耗机会。

教学使用遭遇专属的虚拟教学工具，不从正式背包无限发球，不可交易或带出；消耗规则与界面都标明。首次成功记录与宠物创建一起提交，成功后永久关闭教学资格；不是每次进入地图都重新开启保护。

误击倒、撤退或资源异常时，结束原遭遇，保留原结算记录，在固定教学入口创建一个新的受控遭遇重试。失败教学遭遇没有经验、掉落或通关奖励；教学工具不转为永久资产。成功捕获后也不重复发放另一份教学获宠奖励。

首次选择目标可以来自已配置的两种候选，但每账号只成功获得一次教学保护。普通捕捉与重新刷新的战斗不自动取得该资格。

### 9.3 恢复道具

B0 只需要一种测试恢复道具：治疗一名存活队友最大生命的 30%（向下取整、最低 1），不超过缺失生命，消耗 1 个道具和行动，不回战术点。道具名称、获取和经济数值属于后续内容表；不在测试环境凭空修改正式背包。没有库存、满血、倒下或目标越权时拒绝且不扣除。

## 10. 敌方行为与首领

普通敌人按固定、可复现的优先级策略选择：满足条件且有费用的保护/输出技能，否则普攻。相同目标评分按保存的稳定顺序决胜；不得读取玩家尚未提交的菜单选择。AI 的具体技能与优先级由遭遇配置，不在通用结算中对宠物身份写特判。

首领危险动作提前显示下一次自身行动的意图。B0 示范首领只有三步循环：

1. 整理废铁：一条普攻型主行动，附加自己的护盾，整体只回 1 点。
2. 蓄力：使用基础防御指令，并显示下一次的强力群攻预告，不回点。
3. 强力群攻：消耗 2 点，完成后露出破绽，回到第一步；不足 2 点则普攻回点并维持待群攻阶段，更新意图。

“破绽”先用普通防御下降状态表达，不建立另一条韧性/击破系统。护盾量、攻击倍率和首领最终身份由内容细表决定；示范逻辑必须验证费用与状态顺序，不能因为首领是特殊单位就无限免费施法。

意图描述类型和范围；需要锁定特定目标的强力技能，锁定与失效回退必须写进技能定义。B0 示例只用全体存活敌人，避免临时换目标规则。预告因资源、阶段或目标合法性变化而调整时，界面同步解释，不暗中插队。

## 11. 胜负、收益与战后恢复

| 结果 | 触发 | 收益与处理 |
| --- | --- | --- |
| 胜利 | 己方至少一只存活、敌方无可战斗单位（倒下或已捕获） | 发一次配置的通关/经验奖励，解除占用 |
| 战败 | 己方无可战斗单位；若同一效果双方全灭也算战败 | 不发通关经验与掉落，回据点，不丢宠物或等级 |
| 撤退/放弃 | 当前己方机会主动撤退，或第 12 节的超时 | 不发通关奖励，已捕获和已消耗结果保留 |
| 技术挂起 | 数据、版本或效果异常，不能安全结算 | 保存故障证据并停止新操作，不冒充战败或自动清档 |

主行动内部仍完成其约定效果和允许的后处理后再判终局；某单位一旦 HP=0 就不能继续作为存活目标。双方同灭的优先级明确为战败。回合开始伤害击倒最后单位时立即进入终局，不等待无效输入。

普通战斗经验/掉落只在胜利时统一结算，单个敌人倒下不立即反复发奖。遭遇配置给出结算值；一次结算里敌人的击倒或捕获只能统计一种结果。参与本场的原队员都获得配置的等额经验（包括本场倒下者），新捕获宠物本场不额外分经验；B0 不通过队伍人数分摊总经验。

升级和进化在战后处理，不在正在进行的战斗中悄悄改变已锁定属性。首胜奖励由玩家、遭遇/任务及活动轮次资格唯一约束；可重复遭遇的常规奖励必须单独定义。没有配置完整奖励表的战斗只能用于隔离测试，不能开启正式掉落。

任何正常结束均清除临时状态，下场满血和 3 战术点；不返还已经提交的道具消耗或删除已经捕获的伙伴。B0 暂不设计战后伤势、经验惩罚或扣钱。

## 12. 断线、多标签页、超时与版本切换

一名玩家控制自己的 PvE 队伍时，没有每回合出招倒计时。等待己方输入就停止虚拟时间推进；页面暂停、慢设备或慢网络不改变谁更快。

断线时完成并保存已经接受的原子步骤，然后停在稳定边界；重新认证后继续。已开始的敌方自动步骤可以完成到下一次己方等待点，但不能循环推进到超出已授权流程。恢复等待输入的快照不重跑回合开始效果。

为避免无限占用，B0 设整场不活跃期限为现实 24 小时，自开战或最后一次有效玩家主指令提交后计算；登录、轮询和无效请求不刷新。到期作为“放弃”结算并解除占用，不作为战败惩罚，不返还消耗；重启后检查保存的截止时间。技术挂起期间冻结该期限，恢复时使用剩余时长，不能因服务故障自动放弃。24 小时是原型运营参数，正式开放前需要单独确认并在 UI 提示。

同一账号多个标签页都能读取状态，但只允许一条当前行动指令提交成功。按会话验证玩家，使用战斗 ID、行动机会 ID、revision 和 requestId 防止重复或过期指令。相同请求先查原回执；即使 revision 已变化，也应返回原结果。相同 ID 改参数拒绝；换 requestId 仍不能重复使用同一行动机会。

每场固定规则与内容版本。活动关闭只拒绝新进入，已开战按原版本完成或已批准的放弃策略收尾；新构建不能直接解释旧状态。旧代码与内容无法保留时，先停止开放、维护并明确迁移/终止方案，不给旧战斗自动换规则。

捕捉和战斗结算用各自业务唯一记录保护。技术故障修复从已提交检查点继续，不能为重试重新抽取已确认随机结果；补偿与人工恢复仍由受控运营流程授权。

## 13. 战斗界面与二维表现

探索时操控主角，战斗中使用固定二维舞台；地图坐标和前后视觉位置不产生距离或格子规则。主角只做指挥表现，不显示为第五个行动头像。

行动条展示当前单位及之后最多 8 次预计行动，同一高速单位可重复出现。预测按当前速度外推，标注“预计”，不承诺覆盖未来技能、死亡或状态到期；当前就绪顺序必须与服务端相同。选中加减速技能时可额外预览立即施加后的变化。

核心常驻信息为：当前行动者、各单位生命/护盾/关键状态、双方战术点与己方技能费用。技能选择后突出合法目标、费用、效果、明确的状态参照和可预测伤害；非法目标解释原因。捕捉单独显示资格、教学保护或真实概率，不把护盾误算为目标生命。

只有收到服务端结果才显示正式扣除、获宠和胜负。普攻、技能、防御、道具和捕捉复用一套结果事件。演出由本体动作、挂点、技能特效、命中反馈和音效组成；播放速度与跳过不能改变结算。长演出可以缩短，状态和奖励仍应完整呈现。

不得照抄生成概念图中的等级、替换按钮、属性标签和主角行动头像。现有 animation-lab 的攻击样本只是表现参考，不反向决定技能规则。

## 14. 最小验证战斗与数值例子

### F01：单宠开局

分别选择三个初始候选完成同一类中性教学遭遇。每个候选有正常普攻和至少一个可用主动；保护/辅助选项不能让开局软锁。敌人不能在玩家首次机会前靠极端速度连续击倒它。目标是学会行动和捕捉，不预设必须按唯一按钮顺序才能通过。

### F02：双宠资源与标记

测试快辅 SPD=120、输出 SPD=100、敌人 SPD=90，无初始状态，各自满进度从 0 开始；己方战术点为 3。第一轮先后为快辅 83.3333…、输出 100、敌人 111.1111…。

快辅先用 1 点施加标记，己方剩 2；输出用 2 点主动作触发标记，剩 0；下一次己方普攻后变 1。替代路径是快辅普攻先回至 4，输出用 2 点后剩 2。必须比较即时伤害和后续选择，而不是仅检查按钮可点。

用于算例的输出 ATK=40、技能倍率=1.5、敌 DEF=50、中性：无标记 40，有标记 50。试图保留目标捕捉时，强攻可能不是最佳选择。不得把本例当作对现有 starter_a/b/c 的正式数值赋值。

### F03：四单位与首领

使用输出、保护、标记及第四个不必为治疗职业的队员，验证 4 只同时存在、资源竞争、危险预告与低速价值。首领按第 10 节循环。随后覆盖四单位对四单位，不依赖场上前后位置，不让被击倒者继续占用输入。

战斗节奏记录用“有效主行动数”而不是模糊全局回合。早期试玩可先争取普通遭遇约 6–12 次全场主行动、首领约 18–30 次；这些是调试目标，不是通过测试的强制时限，不靠限制玩家思考制造达标。

## 15. 共创与实现交付边界

常驻系统负责时间轴、指令校验、成本与效果结算、状态寿命、终局、捕捉资产和恢复。具体宠物只配置基础值/技能，或在允许接口内实现条件；首领只配置自己的策略和效果；活动不另建伤害、账号或发奖系统。

每个新内容需要提交定位、基础值与速度、技能费用与效果、状态参照、合法目标、捕获参数/资格、掉落、表现引用和测试用例。特殊需求超过 B0 时，进入常驻规则变更任务，不能隐含在某只宠物代码里。

底层保持“状态 + 指令 + 内容 + 可控随机状态 → 新状态 + 表现事件”。保存参战快照、T/P 或等价等待、tieOrder、当前阶段、状态寿命、双方资源、AI 阶段、随机状态、已提交回执及内容版本；不保存 Canvas 对象或依赖动画回调恢复。

自动敌人步骤、回合开始、玩家主行动与终局需要各自可识别的持久化边界，等待输入期间不持有数据库事务。公共基础接口和表结构在架构正文设计，本稿不预造通用事件语言、类层级或额外微服务。

合作 PvE、PvP、旁观、掉线代打、共享捕捉归属与多人共享战术点使用权属于后续专题。未来两名玩家各控制两只可以复用四单位时间轴，但不是本稿已经批准的联机模式。
